# blog/ — article idea pipeline

This folder turns the work done on the project (refactors, optimizations,
fixes, technical decisions) into a **blog article backlog**, kept up to date
automatically.

## Files

- [`BACKLOG.md`](./BACKLOG.md) — the curated list of candidate articles, grouped
  by theme, each with: angle, available material, and **sources**
  (commits / PRs / docs) so writing can start without re-digging through history.
- `INBOX.md` — **raw** milestones detected automatically, waiting to be triaged
  into `BACKLOG.md`. Generated by CI (see below); ephemeral.
- `.last-scan` — cursor: SHA of the last scanned commit.

## Automatic detection (GitHub Action)

Reliable milestone detection runs **in GitHub's infrastructure**, not inside a
Claude session (the web container is ephemeral and background polling is not
reliable there).

- `.github/workflows/blog-scan.yml` triggers on every **push to `main`**.
- It runs `scripts/scan-blog-milestones.mjs`, which compares `HEAD` against the
  `blog/.last-scan` cursor, classifies the **new code commits** (ignoring previews,
  thumbnails, `metadata.json` and its own machinery) by type
  (`perf` / `refactor` / `feat` / `fix` / other), and writes them to `blog/INBOX.md`.
- When there is material, a **rolling PR** "🤖 Blog — new milestones to triage"
  is opened/updated. Merging it advances the cursor.
- Deterministic, **no API key required**.

Manual runs are possible via `workflow_dispatch` (with an optional `since`), or
locally: `node scripts/scan-blog-milestones.mjs` (override `SCAN_HEAD=<ref>` to
target another head).
