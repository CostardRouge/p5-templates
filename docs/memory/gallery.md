# Gallery — the browser-side snapshot archive

Read before touching `src/lib/gallery/`, the `/gallery` page, the Keep button, the keep-after-export hook or the `gallery.*` agent commands. The vision and what the maintainer settled are in `agent-roadmap.md` (track B); this file is what was built and why.

## What an entry is, and where it lives (2026-10-11)

**Decision.** One entry per PIECE: the whole options document as the form held it (`SketchOption`, cloned), a ~240 px JPEG of the frame on screen, the sketch's route tail (`engine/category/name`), a date, a free title, an origin (`export` | `keep` | `agent`), and a `hadAssets` flag. Never the video, never the uploaded media (`agent-roadmap.md`: 95–99 % of sketches have none; a relaunch tolerates a missing path and the card says "had assets"). **Where**: IndexedDB — the first real browser store in the app (`idbBackend.ts`: database `sketchbook-gallery`, one object store `entries` keyed by `id`, thumbnails as Blobs beside the document; one transaction per call, no long-lived connection; `onversionchange` closes and reopens lazily). A hand-rolled 80-line wrapper rather than idb/dexie: five operations do not earn a dependency. **How to apply**: everything goes through `GalleryStore` (`store.ts`), which is backend-agnostic — `memoryBackend.ts` is what the tests and a runtime without IndexedDB (SSR) get, so nothing checks for the API first; `getGalleryStore()` is the page-wide singleton. The store is observable (`subscribe`) so the page re-reads after its own writes or an agent's in the same tab; another TAB is not notified (no BroadcastChannel yet — reopen or reload the page). **Two IndexedDB traps met while verifying**: `upgradeneeded` fires only when the version RISES, so a database of our name that exists at our version WITHOUT the store (a probe's bare `indexedDB.open( name )` creates exactly that) is unusable forever — `openDatabase` reopens it one version up; and `blocked` is not a failure (the upgrade waits for the other connections, which close on `versionchange`), so it only rejects after 5 s. A headless probe that reads the database must close its connection (or handle `versionchange`), or the app's upgrade waits on it.

## The cap is 500 entries, oldest pruned (2026-10-11)

`GALLERY_CAP = 500`, enforced on every `add` (the oldest by `at` go first; `add` answers the ids it pruned). At ~30 KB an entry that is ~15 MB, far under any quota, and five pieces a week fills it in two years. More than that is what the archive backup is for (below). Raising it is one constant; there is no quota probe on purpose — a `QuotaExceededError` surfaces as a failed keep, not a silent drop.

## Same piece = same canonical document (2026-10-11)

`canonical.ts`: keys sorted at every level, arrays in order, `undefined` dropped, the root `id` (the job a document was loaded from) left out; `fingerprintDocument` is two 32-bit FNV-1a digests plus the length. A keep dedupes against the NEWEST entry of the same sketch only — "nothing changed since the last time" is the question, not "has this ever been kept". `documentHasAssets` spots a `global/…` or `slide-N/…` path (`getScopeAssetPath`'s shape) anywhere in the document; a bundled `assets/images/test/…` default is not an upload.

**"Newest" is `at`, then the id — and the id is random (2026-10-18).** `newest()` in `store.ts` orders by `at` descending and breaks a tie with `id.localeCompare`; ids are `crypto.randomUUID()`, so two entries of one millisecond come back in a coin-flip order and `latestOf` may answer the OLDER one. Not hardened on purpose: real keeps are human or agent gestures far more than 1 ms apart, and a stable tie-break would need an insertion counter persisted in IndexedDB. **How to apply**: a test that keeps more than once and relies on order passes `at` (`KeepInput.at`) on every call — `keep.test.ts` flaked about 1 run in 5 without it, failing PRs that never touched the gallery. Through `gallery.keep`, which takes no `at` (and should not grow one for tests), spy on `Date.now` with a clock that advances on every read, as `galleryCommands.test.ts` does; pinned to a constant, that test's list-order assertion failed 8 / 20.

## Two triggers, one gesture (2026-10-11)

`keepPiece` (`keep.ts`) is the only writer: it clones the document through JSON (as the options export does), sets `options.name` to the sketch's (the sketch page's import handoff matches on it), fingerprints, dedupes against the newest entry of the same sketch (answering that entry, retitled when a new title came), and stores with the frame's thumbnail (`thumbnail.ts` → `captureThumbnailFromCanvas`, decoded from its data URL — a 240 px JPEG is tens of KB, so the data-URL rule of `assets.md` does not bite). **Export**: `ExportPanel.handleExport` keeps after `runExportBatch` resolves with every variant `done` and no abort — one entry per RUN, not per variant, and a gallery failure only `console.warn`s because the files are already delivered. **Keep**: `KeepButton` in the transport bar, between the camera and the record dot (it reads the document through `useFormContext`, so the bar must stay inside `FormProvider`); it reports on itself like the snapshot button — green check (kept), grey check ("already in the gallery — nothing changed since"), red (error) — with `data-keep-state` for a headless probe. Rejected: a Keep entry in the burger menu (the menu is on every page; the gesture is the sketch page's) and keeping on every snapshot (a still is not a piece).

## The page, and reopening a piece (2026-10-11)

`/gallery` (`src/app/gallery/page.tsx` → `components/GalleryPage/`) is a client page over the store: cards newest first at the canvas's own aspect ratio (a Reel and a square read as what they are), a sketch `<select>` and a title search, rename in place (pencil → input; Enter commits, Escape reverts), delete behind one `confirm()`. `robots: index: false` like `/recordings`, which stays the backend's page; the human site map links both. **Opening** goes through the listing's handoff: `stageGalleryEntry` writes the document to `sessionStorage` (`pendingImportOptions`, `name` set to the sketch's) and the card `router.push`es the sketch route; the sketch page consumes it on mount through `handleImportOptions` (strict parse, "Options imported successfully"). The agent's `gallery.open` reuses the same two steps. Rejected: a URL-carried document (`/embed`'s `#o=` is a sketch delta, no slides, no content) and applying through the option store (the form is the source of truth — `agent-commands.md`).

**Trap, fixed in `useFormState`**: the handoff's `reset()` runs in the form's mount effect, its flush is a `requestAnimationFrame`, and dev's StrictMode runs the effect's cleanup right after that first mount — which cancelled the frame. The form held the piece, the sketch kept playing its defaults (a 720 × 720 entry reopened on a 1080 × 1350 canvas) until the next edit flushed everything. The cleanup now delivers a pending value instead of dropping it. Production never double-mounts, but the listing's "Import .json" had the same dev-only symptom. A reopen is verified by reading the CANVAS (`.sketch-canvas-container canvas` width/height), not `document.get`: the form answered the right size the whole time.

**Object URLs for the thumbnails are minted inside the effect that revokes them** (`useObjectUrl`): a `useMemo`'d URL survived StrictMode's cleanup → mount and came back revoked — every other card showed a broken image.

## The backup is ONE JSON file, thumbnails inline (2026-10-11)

`archive.ts`: `{ format: "sketchbook-gallery", version: 1, exportedAt, entries[] }`, each entry as stored with its thumbnail as `{ type, base64 }`. A zip of JSON + JPEGs was weighed (`zipStore.ts` writes one) and lost on the maintainer's criterion, simplest to restore: one `JSON.parse`, no zip READER for a format the app has no other use for, and a file a person can open. Export is `triggerDownload` of `sketchbook-gallery-YYYY-MM-DD.json` (a backup goes to Files, not Photos — no share sheet); import is a hidden `.json` input (`HIDDEN_FILE_INPUT_CLASS`, `assets.md`). **Import merges, never duplicates**: an entry already present by `id`, OR whose `sketch` + `fingerprint` is already there (the same piece kept by another browser under another id), is skipped; nothing already there is overwritten (a title renamed elsewhere stays as it is here); the cap is applied once after the whole batch (`store.addMany`). A bad file is refused naming the problem (not JSON, wrong `format`, newer `version`, a malformed entry by index). Verified: a 22 KB archive of one entry, delete, import → "1 piece added" with the image loading, import again → "0 pieces added, 1 already here".

## The agent's door: five `gallery.*` commands (2026-10-11)

`src/lib/agent/commands/galleryCommands.ts`, on the conventions of `agent-commands.md`: `gallery.keep { title? }` (origin `agent`, the same `keepPiece`; `kept: false` answers the existing entry), `gallery.list { sketch?, since?, until?, limit? }` (`sketch: "current"` for the open one; dates are ISO strings refused when `Date.parse` cannot read them; answers `count`, `total` and summaries with ISO dates, never documents or thumbnails), `gallery.thumbnail { id, maxEdge? }` (the one `ImageResult`; default 512 hands the 240 px thumbnail back as kept — 240 shrank the portrait ones), `gallery.open { id, discard? }`, `gallery.remove { id }`. **`gallery.open` is two existing moves**: the same sketch → `handles.gallery.importDocument` (`parseImportedOptions` + `form.reset`, the import button minus its banner) answering `opened: false, applied: true`; another sketch → `stageImport` (the sessionStorage handoff) then `navigation.open` and the `studio.open` wait, then `applied` = the handoff was consumed within 10 s (`hasPendingImport`) — the new page's own import applies it, and a refusal shows as the banner in the tab. The dirty guard is `studio.open`'s (`history.canUndo`, `discard: true`). The handles are a `gallery` member appended to `StudioHandles` (store, thumbnail, importDocument, stageImport, importPending) — the store itself, not a wrapper, so the commands and the page read one object; the fake keeps a memory store and "consumes" a staged document when `navigation.open` runs.

## Lab 3: what each piece became — Month · Week · Grid (2026-11-13)

**His decision** (lab 3, https://claude.ai/artifact/4FyW781GjteekT5aNcXfEZ, which drew G1 tabs, G2 cards wearing their posts, G3 a month): a HYBRID — one switcher **Month · Week · Grid**, Month by default, else the last view chosen; and **no reflow**: the page paints in its final view and layout from the first frame. **What was built**: Month = G3's calendar, six fixed weeks (`calendar.ts` `monthGrid`, always 42 days, so paging never changes the height), each day's vignettes (published plain, planned ringed blue, failed ringed red, a draft dashed), four then «+N». **On a phone a cell is too small for a picture** (G3's flaw): cells show DOTS in the states' colours and the day tapped (today first) is listed UNDER the month with vignettes, marks and state — the list is the page's last block, so its height moves nothing. Week = Atelier's Planned strip at parity (`freeSlots` is `weekStrip`'s slot rule: future, untaken, no live post that day, EVERY post of the account counted). Grid = the old grid, each card wearing G2's overlay (marks with state + «Sun 10:00» / «failed» / «published») and a line («Planned · Sun 10:00», «Posted on 4 · 11 Nov», «Bluesky failed · 3 out», «Not posted»), chips All · Planned · Published · Failed · Not posted (a piece answers to its NEWEST send). Every view's click opens the **sketch sheet** (`SketchSheet.tsx`): every send of the sketch, each account with *View ↗* (`releaseURL`) or its state, a failure's first sentence + `failureHint` + the raw text on demand, *Take back* / *Delete the failed post* (one `DELETE` per post not out; `publishStore.forgetPosts` drops only those ids), *Open in Postiz*, the pieces kept (each reopens), *Open the sketch*. **A card's click now opens the sheet**, no longer the studio — reopening is one more click, through *Open the sketch* or a kept piece. **Differs from the lab**: no «Publish another…» button (Export › Publish is one click from *Open the sketch*); the strip is a view of its own rather than G2's band over the grid.

**Without a Postiz** Month and Week lay out the PIECES by the day they were kept (a calendar of the archive, «Pieces kept, by day»), Grid has no overlays and every chip but All counts 0; the status line says to connect Postiz.

**A send knows its piece** (`Publication.pieceId`, set by Export's publish run from `keepExported()`'s entry id, carried by its *Send again*). An older send, and `publish.schedule` (which keeps no piece), fall back to the newest piece of the same sketch kept no later than the send + 60 s (`sends.ts` `pieceOfPublication`). `buildSends` joins `publishStore.allPublications()` with Postiz's listing by post id; without a listing a draft reads `draft`, a send still ahead `queue`, anything else «Sent» — never a guess. Postiz's own date wins over the one asked (a post moved in Postiz lands on its new day).

**Postiz is read ONCE when the page opens** (Q6, Atelier's window): 5 weeks back, 8 ahead (`postizWindow` asks a week more each side); the calendars page only through that span when a Postiz is kept, *Open Postiz* beyond. The read is the WHOLE list (the free slots need every app's posts); what is DRAWN is only the sends this browser kept, so another app's posts never show.

**No reflow, and how it is held** (measured, CLS 0 in all six cases: Month, Week, Grid × 1440 × 900 and iPhone 13, with and without Postiz): (1) the view and the time zone travel in a COOKIE, `sketchbook-gallery` = `view~Zone` (`view.ts`), read by `src/app/gallery/page.tsx` — so `/gallery` is now **dynamic** (ƒ), which is accepted: a `localStorage` read paints Month then swaps, and Next's inline-script recipe (`preventing-flash-before-hydration.md`) would have meant rendering all three views. The server also computes TODAY in that zone and hands it down, so the today mark hydrates identically; the client corrects the zone after mount (rhythm's zone once a Postiz is kept, else the browser's) and writes it back. (2) Everything late lands in frames already sized: fixed-height month cells, a toolbar whose widths are fixed or flexed — **the trap**: the sketch `<select>` sized by its longest option grew when the archive loaded and pushed a phone's toolbar onto a new line (CLS 0.20); the legend's slot has a fixed width and the two legends carry different keys (a node replaced is not a shift, a node resized and moved is). (3) No tile is laid before everything it depends on is read (`sendsKnown`): a tile that changed «sent» → «failed» under the eye resized its pill and counted. (4) The week strip's scroll to today is done by an INLINE SCRIPT before the first paint (`InlineScript`, Next's guide), plus a layout effect for soft navigations. **How to measure**: headless Chromium, a `PerformanceObserver` on `layout-shift` (buffered) from an init script, the page's JS held back by `page.route` until a first-paint screenshot is taken, then released; compare element rects before/after and the summed CLS (the session's scripts were in its scratchpad, not committed).

**Hydration trap met** (`MenuBar.tsx`): with a Postiz kept, `/gallery` threw React #418 — the layout's Suspense boundary around the menu hydrated AFTER the page's `MenuBarSlot` registered and its IntersectionObserver reported visible, so the menu rendered inline where the server had drawn the floating button. `renderInline` now waits for the menu's own mount. Any page that grows heavy can expose this race again; keep context-driven markup out of a late-hydrating boundary's first render.

**Posts from another device (Q3, my recommendation taken by default — droppable as its own commit)**: the gallery lives in one browser, Postiz sees every send. `foreignSends` (`sends.ts`) takes Sketchbook's posts (`sketchbookPosts`: the tag — which exists in his Postiz since 2026-11-13) that no send of this browser kept, groups them by Postiz's `group`, and ties each to the sketch its CAPTION links to (`sketchFromCaption`: `{link}` holds `/sketches/<engine>/[<category>/]<name>`; the key is `<engine>/<name>`). A caption with no link is left out (a sheet is a sketch's). They show on the calendars and in the sheet with the catalogue thumbnail (`/assets/images/templates/<engine>/<name>/thumbnail.webp`, a missing one leaves the frame empty) and «from another device»; never on a card (no piece here). No metadata import: the catalogue JSON would have joined the gallery's bundle for a check the thumbnail's 404 already makes.

**Send again from the sheet (Q4, my recommendation — its own commit)**: the gallery keeps no video, so a failed send is a NEW render and send: `askSendAgain` (`src/lib/postiz/reopen.ts`, Atelier's `askSendAgain`) puts `{ sketchKey, channelIds, at }` in `sessionStorage`, the piece is staged through the usual handoff and the sketch opens; `SketchOptions` takes the ask once on mount (same `<engine>/<name>`, under two minutes old), patches the sketch's draft to `mode: "publish"` with only those accounts, and opens the Export dialog. The variant each account takes follows the usual routing (`publishing.md`): nothing of the failed send's choice is replayed. A send with no piece here opens the sketch with its defaults. Verified headless on the stub: the iridescent send's Bluesky failure → the sketch opened on Export › Publish, Bluesky alone ticked, the verb on the next free slot.
