# Interaction sources — the device-backed collectors

The listener side of the interaction layer: `src/sketches/p5/utils/interaction/index.js` (the `_FLAT_COLLECTORS`, one per source) and the pure maths modules beside it (`gyroMath.js`, `pinchMath.js`, `gestureMath.js`). Read this before touching how a sensor, a camera or a controller becomes a pointer. What a pointer becomes once it is a *channel* — the bindings, the pastille, the manifest — is `interaction-bindings.md`.

## The gyroscope is a calibrated pose, not raw angles

2026-09-21 — The source read as dead on a phone, and no log said why: the collector mapped `beta` over ±45° around **0°, a phone lying flat**. Held at reading height (beta ≈ 40–70°) the pointer was pinned to the bottom edge, and near vertical `gamma` flips sign, so the marker jumped along that edge. The maths now lives in `gyroMath.js` (`stepGyroscope` over an explicit `freshGyroState()`, unit-tested); index.js only stores what the events report.

- **Calibration is the fix, not a wider clamp.** `calibration: auto` makes the first reading after enabling the centre; toggling the source off and on re-centres (the collector sees the `frameCount` gap — a paused sketch does not advance `frameCount`, so pausing does not). `flat` is the pre-existing behaviour, `custom` reads the pad (x = roll/gamma, y = pitch/beta). Any sketch can call `recalibrateGyroscope()` on a tap.
- **Four signals in the `source` conditional group**, `range` in each mode's own unit (°, g, m/s², °/s): `tilt` (the angles), `gravity` (the sine of the angles — projected gravity, continuous through the vertical where gamma alone flips), `acceleration` (linear, through a peak-hold envelope with `release`) and `rotation` (the rate integrated with a dead zone: a joystick with no spring). A branch switch rebuilds the object from each field's `default`, which mirror `GYRO_MODE_DEFAULTS` — keep the two in step.
- **Gravity is derived from the orientation angles, never read from `accelerationIncludingGravity`**: that field's sign is inverted on iOS relative to Android, the angles agree everywhere. Linear `acceleration` carries the same iOS sign quirk; `invert` is the documented remedy, not a detection.
- **The listener keeps the acceleration PEAK between frames.** Motion events run at ~60 Hz and a heavy sketch draws at a fraction of that; sampling the latest value would miss the spike a shake is. The collector consumes the peak once per `frameCount`.
- The natural mapping is the **marble**: raise the top edge → pointer DOWN, right edge down → pointer right. `invert.y` gives the "aim" feel. `screenRotation` re-expresses the device vector by `screen.orientation.angle` (90 = top edge pointing left; legacy `window.orientation` -90 = 270), derived on paper and checked in unit tests, not yet on a real landscape phone.
- **The absence rule applies**: no reading → no pointer (it used to publish the centre, indistinguishable from a phone held still). Desktop Chrome fires ONE `deviceorientation` with null angles on load — ignored, and remembered as "no sensor on this device".
- **iOS permission**: `requestPermission()` is called right away — it resolves without a gesture once granted in the page session, so a re-enable costs no extra tap — and only when that rejects is a `click`/`touchend` handler armed, in the **capture phase**, so a control that stops propagation cannot eat the one tap the prompt waits for. Both `DeviceOrientationEvent` and `DeviceMotionEvent` are asked inside the same gesture. `initInteraction` arms it at setup when the source is already on, so a sketch paused while the form is edited still gets its prompt. A denial persists for the page's life (reload to be asked again).
- **HTTPS is required** for the events on iOS, and the LAN dev server (`local-development.md`) is HTTP. `getGyroscopeStatus( gyro )` reports the state (`awaiting-gesture`, `denied`, `listening`, `active`, `unsupported`) with a hint, and the overlay legend prints it (`gyroscope: tap the page to allow motion access`, `… not HTTPS …`, `… no motion sensor …`) — the one source whose silence is otherwise indistinguishable from a still phone.
- The `/embed` iframe snippet carries `allow="camera; microphone; gyroscope; accelerometer"`: Chrome's permissions policy blocks the events in a cross-origin frame without it. The frames on steevepommier.com/motion need the attribute on that side.

**Verifying needs no phone.** Dispatch `new DeviceOrientationEvent( "deviceorientation", { beta, gamma } )` and `new DeviceMotionEvent( "devicemotion", { acceleration, rotationRate } )` on `window` under Playwright — the real listeners read them — and read `--ch-gyroscope-x` / `-y` off `:root` (build with `INTERACTION_BINDINGS=true`; `channelBridge` removes a channel's vars when it leaves the snapshot, so an empty var is a real absence). Form ids are `sketch.interaction.gyroscope.<field>`; the `Signal` conditional group and `Invert` are collapsed AND unmounted until their label is clicked. Measured on `interaction-test` at ~19 fps: first reading → 0.5/0.5; +15° on the 30° range → 0.75/0.75; past the range → the edge; `invert.y` → 1; a +8 m/s² shake peaks at 0.94 and settles to 0.5; a steady +90°/s roll walks x to 1.
