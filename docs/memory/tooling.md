# Tooling

Read before touching TypeScript, ESLint, the git hooks, the merge drivers or anything in `scripts/`.

## Two TypeScript compilers, and why moving to one breaks the repo

2026-08-20 — TypeScript 7 is the native (Go) port and its npm package no longer exports the classic JS compiler API — which ts-jest and typescript-eslint still require, and which they exclude by peer range. So the tree carries both: `typescript` 6.x (JS-based, full API) for ts-jest, typescript-eslint and `next build`, and `typescript7` (an alias of `typescript@7`) for `npm run typecheck`. **How to apply**: `npm run typecheck` is the authority on type errors — it covers everything in `tsconfig.json`, tests included, in about 8s where TS 6 takes ~33s, and the two agree on this codebase. Do not "simplify" by promoting `typescript` to 7: lint and test break immediately. Note also that `tsconfig.json` sets `types: ["node", "jest"]` explicitly, because TS 6+ stopped auto-including every `node_modules/@types` package — a missing global type is usually that, not a missing dependency.

## Formatting is enforced, not agreed

2026-08-20 — There is no Prettier: `@stylistic` rules inside `eslint.config.mjs` are the formatter, and `opencode.json` explicitly disables Prettier (along with uv and ruff) so an agent's editor integration cannot fight them. The style is unusual on purpose — spacing inside `( … )`, `[ … ]` and `{ … }`, double quotes, semicolons, and one item per line as soon as an array, object, call or import has more than one entry. `lint-staged` runs `eslint --fix` on every staged `js/jsx/ts/tsx/mjs/cjs` file at commit time. **How to apply**: do not hand-format to match; write it roughly and run `npm run lint:fix`. On a PR, commenting `/fix-lint` triggers `.github/workflows/lint-fix.yml`, which runs `lint:fix` and pushes the result back to the branch (collaborators only, never to a fork); since 2026-10-19 its commit is titled `Apply the lint fixes` — a bot's commit follows the same title rule as a human's (C3: no `chore:` prefix), where it used to write `chore: apply lint --fix`.

## Generated-file merge conflicts are resolved by git, not by hand

2026-08-20 — Two branches that each add a sketch will always conflict in the generated catalogue, and a textual 3-way merge of those files is meaningless. `.gitattributes` therefore sets `merge=union` on `sketchModuleRegistry.ts` and `sketchOptionsRegistry.ts` (append-style maps — git's built-in union keeps both sides, and GitHub honours it too) and `merge=sketch-metadata` on `metadata.json`, a custom driver in `scripts/git-merge-metadata.mjs` that unions the JSON array by sketch identity. A driver name is only a label until it is defined in git config, which is per-clone and not committable — so `scripts/setup-git-merge-drivers.mjs` wires it up from the `prepare` script on every `npm install`, and exits silently outside a work tree. **How to apply**: if a `metadata.json` conflict ever shows up as raw conflict markers, the driver is not configured — run `npm install` (or the script directly) rather than resolving it by hand. 2026-10-22 — **The driver merges field by field against the ancestor (`%O`)**, because the union it replaced kept OUR copy of a sketch present on both sides and ORed five booleans, silently dropping every other field the other branch had added — a 174-commit catch-up lost `main`'s new `description` / `tags` on 8 sketches. Each field now takes the side that changed it; a deletion is honoured when the other side left the entry untouched; only a non-flag field changed differently on BOTH sides keeps ours and prints a warning to run `npm run sketch:meta:write`. `scripts/__tests__/gitMergeMetadata.test.ts` runs the driver as git does; replaying that real merge, the driver's output is byte-identical to the regenerated file. **How to apply**: a new metadata field needs nothing here; a new flag that means "an asset exists" joins `PRESENCE_FLAGS`.

## Hooks: what actually runs

2026-08-20 — `.husky/pre-commit` regenerates and stages the sketch catalogue when a sketch or template asset is in the commit, then runs `lint-staged`. `.husky/pre-push` is entirely commented out — it would run `npm run build` with `NEXT_BUILD_DIR=/tmp/p5-templates-build`, and `.github/workflows/lint-fix.yml` records the reason as "a known issue with NEXT_BUILD_DIR resolution". CI workflows set `HUSKY: 0` during `npm ci` so hooks do not run in Actions. **How to apply**: nothing validates a push locally today — run `npm run check` yourself, plus `npm run build` for sketch or route changes. Never `--no-verify`: the pre-commit hook is what keeps the generated catalogue from drifting, and skipping it produces a commit that fails `sketches.test.ts` in CI.

## Security bumps go through `npm update <pkg>`, not `npm audit fix`

2026-10-02 — `npm audit fix` resolves every advisory it can in one pass, and on this tree that drags the `prisma` CLI a minor ahead of `@prisma/client` (7.10 vs 7.9) as a side effect of fixing `@prisma/config`; the CLI generates the client into `src/generated/prisma`, so the two must move together. What is left after a targeted update — `deepmerge-ts` and `mysql2` under the Prisma CLI — is only fixable by downgrading Prisma to 6 (`--force`), and neither is reached at runtime (Postgres, not MySQL). **How to apply**: name the vulnerable packages, `npm update --ignore-scripts <pkg…>` (lockfile only — the ranges in `package.json` already admit the fix), then `npm audit --omit=dev` to confirm, and run check + build. Bump `prisma` and `@prisma/client` together, deliberately, never as a side effect.

## `@types/node` follows the Node the build runs on (2026-10-09)

CI and both Docker stages run Node 24 (the Playwright base image installs `node_24.x` from nodesource, in v1.59 and v1.62 alike), so `@types/node` is `^24`, not the newest major: `^26` typechecked Node-26-only APIs that crash in the container. **How to apply**: bump `@types/node` to the major in `.nvmrc` (what CI reads since 2026-10-19) and the Dockerfile's image, in the same commit as them, and regenerate the lockfile with npm 11 (`undici-types` moves with it); Dependabot is told to never cross a major on it (`.github/dependabot.yml`). Node 26 becomes LTS on 2026-10-28; do not follow it before CI does.

2026-10-24 — **Node 26 waits on Playwright.** The portfolio moved to 26 (C14, 2026-10-23), but the base image (v1.64.1, and Playwright's `main`) still installs `node_24.x`; a Node-26 PR (#426) was closed unmerged for the crash risk above. The repo stays on 24 by a written exception in `second-brain`'s `portfolio.json`. **How to apply**: when a Playwright release ships Node 26, raise `playwright`, the three `FROM` tags, `.nvmrc` and `@types/node` together, and check the image's `node --version` before merging.

## Tailwind 4: CSS-first config, and what the migration traps were (2026-10-22)

2026-10-22 — Tailwind is 4 (`@tailwindcss/postcss` in `postcss.config.mjs`; no `tailwind.config.ts` — the colour tokens, the `--font-sans` pin, keyframes and animations live in `@theme` at the top of `src/app/globals.css`). Sources are auto-detected (every non-ignored file, sketches included), not listed. **Traps**: (1) `npx @tailwindcss/upgrade` rewrites EVERY string that looks like a class, data included — it turned a canvas op `"ring"` into `"ring-3"`, a test fixture `"blur"` into `"blur-sm"`, and the interpolated variable `${ ring }` into `${ ring-3 }` (a TS error caught only by the build); it also wrapped the HSL tokens in `@layer utilities` and added a grey border fallback this repo does not need. Review its whole diff outside `className`. (2) The Dockerfile copied `tailwind.config.ts` and the lint scripts named it: deleting the file breaks the image build, which CI does not run on a PR. (3) 4.3's default sans stack starts at `-apple-system`/Roboto: pinned back to 3's (`ui-sans-serif, system-ui…`) in `@theme`. (4) 4 dropped two preflight defaults, re-added in `@layer base`: a pointer cursor on buttons and the grey-400 placeholder. **Accepted on purpose**: in 3 a responsive size (`sm:text-base`) overrode an explicit `leading-*` on the same element; 4 honours the `leading-*` at every width, so desktop paragraphs now have the relaxed leading phones always had and the hero's `leading-[0.95]` applies — measured by a computed-style + full-page pixel diff of nine pages × two viewports, every other diff being an equivalent expression (`translate` instead of `transform`, `space-y`/`divide` on the other side, `oklab` colours, `outline-hidden`). Hover variants only fire under `(hover: hover)`, so a tap no longer leaves a hover stuck on touch. **How to apply**: bare data-attribute variants (`data-focus:…`) work now; `data-[focus]:…` still does. A theme token is a `--color-*` in `@theme` referencing the HSL triplet (`hsl(var(--x))`); opacity modifiers (`bg-hover/50`) work through `color-mix`.

## Dependabot: C20, monthly, one minor-and-patch PR (2026-10-21)

2026-10-21 — `.github/dependabot.yml` follows C20 of the portfolio spec: monthly, 7-day cooldown (30 for a major), every minor and patch of npm in ONE `minor-and-patch` PR, family groups for a major listed first (`react`, `next`, `eslint` incl. `@stylistic/eslint-plugin`, `tailwind`, `prisma`, `jest` incl. `ts-jest`), any other major its own PR (≤ 3 open); actions grouped; `docker` and `docker-compose` watched. Why: weekly unrelated PRs, each red for a reason of its own, piled up across the portfolio. Held, each with its reason in the file: `@types/node` major (follows `.nvmrc`); `typescript` major (two compilers, above); `tailwindcss` major was held until the 4 migration (#411 closed red, lifted 2026-10-22, entry above); `playwright` (npm, every version) AND the Playwright image (docker, every version) — the drift test holds them equal and a Dependabot PR carries one ecosystem only, so it was red by construction (#406, closed): raise both by hand in one commit (`deployment.md`), never lifted; `postgres` major in compose — a new major cannot read the old data directory. **How to apply**: a red Dependabot PR is never left open — fix the repo in its own PR, or add an `ignore` with its reason here and close the PR; never merge it red, never push to its branch; no auto-merge. Dependabot security updates must be on in the repo's Settings → Code security (the owner's switch).

## `.gitignore` traps worth knowing

2026-08-20 — `src/generated/prisma` is gitignored, so a fresh clone has no Prisma client until `npm install` runs `prisma generate` via `postinstall`. "Missing module `@/generated/prisma`" on a fresh checkout means that, not a lost file.

2026-08-20 — **`/public/assets/libraries` and `/public/assets/images/samples` are in `.gitignore` but their current contents are tracked anyway** — 21 and 13 files, added before the rules and kept because `.gitignore` does not apply to already-tracked paths. Sketches import straight out of the first one (`import Matter from "@/public/assets/libraries/matter.min.js"`, `scripts.load( "/assets/libraries/decomp.min.js" )`), so those vendored files are load-bearing. **How to apply**: a *new* file dropped into either directory is silently ignored — `git add` refuses it without `-f`, and the sketch that imports it works locally and breaks in CI and in the Docker image. If you vendor a library, force-add it and say so in the commit body. Never untrack what is there: the sketches that import it stop rendering.

## A JS helper's JSDoc is a type contract for the TS tests that call it

2026-09-21 — `npm run typecheck` and `next build` both type-check `__tests__/*.test.ts` against the JSDoc of the `.js` modules they import (`allowJs`), so `@param {number} cfg.width` on a destructured-with-defaults parameter makes the field **required** for every TypeScript caller — a test passing `{ width: 0.3 }` to a function whose signature also destructures `hold` fails typecheck, and the build fails with it, while jest (`diagnostics: false`) stays green. Same for a `{"a"|"b"}` union, which rejects a `string` drawn from an exported list. **How to apply**: a parameter that has a destructuring default is documented as optional, `@param {number} [cfg.width=0.3]`, and the object itself as `[cfg]` when the whole thing can be omitted (which also needs `= {}` on the destructuring); document an enum as `{string}` with the values in prose unless every caller really holds the literal type. Jest passing is not the signal here — run `npm run typecheck` before calling a helper-plus-test done.

2026-08-20 — `.env` and `.env.*` are ignored with a `!.env.example` negation. The negation is required: `setup.sh` copies that template on a fresh clone, and the previous blanket `.env*` made the template impossible to commit. The template must hold no secret value — see `security.md`.

## Generated or copied files must be in ESLint's ignores, or the pre-commit hook rewrites them

2026-10-10 — The pre-commit hook runs `eslint --fix` on every staged `.js/.mjs/.ts` file, so a generated file that is drift-tested byte for byte breaks the moment a commit stages it — typically a merge of `main` that brings a regenerated copy. It happened to `public/mcp/sketchbook-studio-mcp.mjs` (compiled from `scripts/mcp/studioRelay.ts`, checked by `scripts/mcp/__tests__/studioRelay.test.ts`): the merge commit carried a restyled bundle and the drift test failed. **How to apply**: any committed build output goes in `eslint.config.mjs`'s `ignores` (`src/generated/**`, `public/assets/libraries/**`, `public/mcp/**`, `.github/release.mjs`); after a merge, `git diff origin/main HEAD -- <generated files>` must be empty.

2026-10-24 — The same trap had restyled `.github/release.mjs`. **The shared workflows** (`.github/workflows/registry.yml`, `release.yml`, `.github/release.mjs`) are copied byte for byte from `second-brain/system/meta/common-project-spec/shared/`, never from another repo, and their `check` jobs run on `vars.CI_RUNNER || 'ubuntu-24.04'` (never set here: the repo is public).

## The portfolio standard, adopted 2026-10-19

2026-10-19 — `COMMON-PROJECT-SPEC.md` in `second-brain` (the maintainer's standard for every repo of the portfolio; levels validated on 2026-10-19) is applied here. In force since that date: `CLAUDE.md` states the repository's visibility (PUBLIC, so a Registry block carries `Project:`, ticked boxes and one `Log:` line and nothing else); the commit template ends with whatever attribution trailer the harness asks for (K2), never a spelling of this repo's own; `.claude/commands/memorize.md` is the canonical text (K6: a cloud session pushes its branch and opens or updates its pull request, a local one never pushes); `AGENTS.md` is a symlink to `CLAUDE.md` (K1). The rule numbering stays this repo's own — rule 3 is the sync-with-`main` rule, so the registry is rule 4 and versions rule 5 — and the spec records that exception. The toolchain (C14, N1): `.nvmrc` holds the major CI and the image run (24) and `engines.node` the floor (`>=22`, the lockfile's root entry regenerated with npm 11 to say the same); the four CI jobs and the lint-fix workflow read `node-version-file: .nvmrc`; the Docker base image carries an exact tag, held to the lockfile by a test (`deployment.md`). Dependabot follows C20 since 2026-10-21 (next entry). **Trap**: the container that adopted the spec ran Node 22.22.0, under `lint-staged@17.2`'s declared floor (`>=22.22.1`): `npm ci` only warns (`EBADENGINE`), but the hook may refuse on a stricter npm — the floor to hold is `.nvmrc`'s 24. **How to apply**: where `CLAUDE.md` and the spec disagree, the spec wins and `CLAUDE.md` is fixed in the same commit; a change to the spec reaches this repo only by being pasted here (there is no distribution mechanism, spec §9).
