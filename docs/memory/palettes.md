# Palettes — read before touching `utils/palettes.js`, `utils/paletteGlsl.js`, a sketch's palette picker or `colors.palette`

## A house colour function is a FORMULA palette

2026-10-11 — The palette presets left the iridescent category for `src/sketches/p5/utils/palettes.js` (import-free, so `options.ts` files and runtimes both read it). A palette is stops + hardness, or a `formula` id (`rainbow` = the peaks' `colors.rainbow`, `oil-slick` = the shaders' cosine `iridescent()` spectrum) evaluated at every texel of the 256-wide ramp. **Why**: the maintainer feared losing his gradients to "a succession of flat colours" — and the first Rainbow preset (12 sampled stops, smoothstep between them) did drift up to 12/255 a channel; a formula bake stays within rounding (0.5/255). A formula palette's `stops` (24 samples) only draw the picker tile. **How to apply**: a new house colour function becomes a formula in `PALETTE_FORMULAS`, never a hand-sampled stop list.

## The shader sketches

2026-10-11 — **The shader sketches take a palette through the cosine they already had, with "original" the untouched default** (the maintainer's call: the shader families he uses most first, the background left alone). `PALETTE_IRIDESCENT_GLSL` (braidShader.js) keeps the exact cosine arithmetic while `uPaletteOn` is 0 and reads `uPaletteRamp` at `hueSpread · t + phase / 2π` when a preset is picked — one ramp loop per cosine period, so hue speed / spread / phase still scroll it and saturation / brightness still grade it. `shaderPalette( colors )` hands the texture (baked once per id) and the switch; `shaderPaletteFormFields` / `shaderPaletteFormValues` add the picker and an off-by-default "use the palette's background" checkbox (the paper's two colours averaged into the sketch's ONE `backgroundColor`, alpha kept) to the colour group. Migrated: braid, rings, sculpt (v1–v9), flip v1 / v3, flowers-shaders, torsade-shaders, torsade v7, signals 02 / 03, dragon-corridor — 41 sketches, the 15 that had a local copy of `iridescent()` now import the chunk (all copies were byte-identical). Verified: "original" renders pixel-identical (delta 0) to the pre-migration build on nine sketches of every family. Second pass (same day): the `paletteRainbow` GPU ports (noise-grid v2, v5–v8, v10–v12) call `paletteRainbowRamp` (`utils/paletteGlsl.js`, which also holds the shared `paletteRamp()` sampler), reading the ramp at `(hueOffset + hueIndex) / 2π` and keeping `/ opacityFactor`; their "Original" is the exact rainbow (`shaderPaletteFields( "rainbow" )`). shader-loops keeps its four house formulas as its OWN palette ids (`own:` in `shaderPalette` / `shaderPaletteBackground`, so the shared `iridescent` preset, a different look under the same id, is left out of its picker) and reads the ramp at `hueSpread · value + loopHue` for the shared ones. flip-v2 takes the palette on both renderers: shader cards through the chunk, stroke cards and the per-cell tint through `paletteColorAt( colors, x )`, a CPU read of the same cached ramp interpolated as the GLSL does (body darkened, core washed toward white, tint washed 42% — the HSB path's saturation/brightness mapped onto RGB); the palette id is in the card cache key. Verified: "original" pixel-identical to the pre-change build on noise-grid v2 / v5 / v10 / v12, shader-loops (own iridescent / rainbow / purple) and flip-v2 (strokes and shader). Left out on purpose: noise-grid v1 (its own paletteA / paletteB / index select); noise-grid v3 / v4 / v9 and peaks-shaders-sphere went with the 2D pass (below).

## The 2D sketches

2026-10-13 — **A 2D sketch's palette is the id of a colors.js function, and the shared presets extend that same list.** About thirty 2D sketches already had a select of house functions (`rainbow`, `rainbowCrazy`, `test`, `purple`, `darkBlueYellow`, `purpleSimple`, `green`, `black`) — sometimes at `colors.palette`, the very path the shaders use — so a second, implicit palette read from `colors.palette` would have collided with them. Instead every 2D picker is ONE `palette-picker` over `housePaletteOptions( ids )`: the sketch's own functions first ("Your own", same ids, same order, swatches from formulas in `PALETTE_FORMULAS`), then the shared presets minus `rainbow` (it IS the house function). Stored ids, presets and `/embed` URLs resolve exactly as before. **Runtime**: `colors.palette( id, fallback )` (colors.js) returns the house function of that name, a shared preset read off the cached ramp with the house signature (`( hueOffset + hueIndex ) / 2π`, divided by `opacityFactor`, `min` / `max` / easing ignored), or `fallback`'s house function — so `PALETTES[ name ] ?? colors.rainbow` became `PALETTES[ name ] ?? colors.palette( name )` and a direct `colors.rainbow(` became `colors.palette( options.sketch.colors?.palette )(`. A sketch whose main colour was `colors.test` (half of trace-vectors) keeps `test` as its own default. A secondary function (trace-vectors v6 / v8's purple, noise-grid v3 / v4's darkBlueYellow) is left alone. **Background**: the step-3 checkbox was replaced the same day by the background control's "Palette paper" source → `backgrounds.md`. **GPU paths**: splines' glow batch (`glowBatchGpu.js` `setPalette()`, ramp on unit 0) and peaks-shaders-sphere (`peaksFieldGpu.js` `render( { palette } )`, ramp on unit 1, read in the VERTEX shader — which already reads the Perlin table there, so the earlier "vertex texture fetch is not guaranteed" deferral was wrong). Scope: 95 sketches; mask-v1 only mentions the rainbow in a comment.

2026-10-13 — Traps of a scripted migration over many `options.ts`: a new `colors` group in `formValues` REPLACES one inherited through a spread (`...gridTraceFormValuesBase` — v14 lost its hue values until it spread `gridTraceFormValuesBase.colors`), and a new group in a `formConfiguration` that spreads a shared one hides the shared fields (trace-vectors v15 / v16 lost their hue sliders); shared form modules (`trace-vectors/_form.ts` `colorsForm`, `_grid-form.ts`) take the field once. Check every target for top-level spreads before inserting a group.
