# The `iridescent` category

Read before adding, editing or measuring a sketch under `src/sketches/p5/sketches/iridescent/`, or touching its material (`_iridescence.js`, `_form.js`) or its mesh renderer (`utils/spikeMeshGpu.js`, the `spikeShape` hook). The general sketch rules (versions are added, the catalogue is generated, a name is a public URL, an `options.ts` never reaches the p5 runtime, the preview generator) are in `sketches.md`; the palette picker in `studio-ui.md`.

## The `iridescent` category: one ramp material, two renderers

2026-10-09 — `src/sketches/p5/sketches/iridescent/` is a MATERIAL first and sketches second. The reference (a screen recording of a 3D flower whose petals sweep through green / cream / pink / blue / navy as it turns) is a looping colour ramp read by the viewing angle plus a time drift — thin-film iridescence as a lookup, not a lighting model. `_iridescence.js` owns the runtime: the fragment GLSL (`iridescentShade( n, v, dist, cell, pos, structure )`: ramp coordinate = combine( facing, lit, structure ) × `bands` + stagger + wave + offset + drift — three SHAPE terms each with a selectable formula and easing curve, two OFFSET terms laid along any coordinate of the structure (spike index / column / row, a position axis, radial, distance, angle; the stagger static, the wave travelling a whole number of wavelengths per loop with a sine / triangle / saw shape), `fold` wrap-or-mirror past the ramp's end, a drift of a WHOLE number of cycles per loop), the ramp baked to a 256-texel RGBA row from an `item-list` of colour stops with a `hardness` pinch, and the per-frame uniforms; `_form.js` owns the form blocks (material / background gradient / rendering / rotation) and **imports nothing** — see the options-loading rule in `sketches.md`. A sketch declares the structure's size and main axis (`materialRender( …, { scale, axis } )`) so the position axes read as 0..1 whatever its units; the mesh renderer hands the fragment the cell as (column, row, index) fractions and the model-space position, and v4 builds the same from its pipe index and height. **Named palettes are presets, not new controls** (2026-10-09): `_form.js`'s `PALETTES` (two classics — `rainbow`, the peaks originals' `colors.rainbow` sampled at twelve steps on their black, and `iridescent`, the reference-video ramp the custom look starts from, kept as a preset so it survives a custom edit (both asked for by the maintainer 2026-10-10) — four Risograph-ink looks, acid Y2K, liquid chrome, holo foil, beetle shell, thermal, vaporwave, cyanotype, seventies, bauhaus) and the `ramp.palette` field, picked from swatches with the `palette-picker` control (`studio-ui.md`) — `resolveLook()` swaps in the preset's stops, hardness AND — while the background's `source` is `palette`, its default — the background (`paper`), because a riso ink set on the reference's blue-grey reads wrong; `custom` (the default) keeps the form's own, so nothing the maintainer tuned moves. The riso palettes put the paper itself in the ramp as an unprinted stop plus an overprint mix, at near-flat hardness; `finish.grain` (a static screen-space hash jittering the ramp coordinate, cell size × the supersample / render scale so it holds on screen, baked into the permutation) is what turns their band edges into a print stipple — kept independent of the preset so any palette can take it. **Every select and curve is a shader PERMUTATION, not a uniform**: `materialVariant()` keys the choices, `iridescentShadeGlsl( variant )` inlines them (the easing key IS the GLSL function name, `applyEasing`'s dispatch is never called), and `materialRender` hands the renderer `shade: { key, glsl }` — `spikeMeshGpu` rebuilds its program when the key changes, v4 keeps one `noiseFieldGpu` renderer per key. The uniform version was built first and measured 5× the whole material under SwiftShader (sphere 1031 → 3411 ms a frame) even with every curve linear and every offset term at 0: software GL predicates a uniform `if` chain rather than branching, and five dispatches over 31 easings per fragment are what it then executes; baked, the default costs what the first build did (866 vs 964 ms on the dev server) and every option on costs 12% more. A real GPU hoists uniform branches and would not have shown this — which is exactly why the bench is run before trusting a change. Three rules came out of the bench. **The facing term is the angle, not `1 - cos`**: on a sphere most of the projected area lies within 30° of the lens, where `1 - cos` has barely moved, so the first build was one flat colour with bands crammed into the rim; `acos( |n·v| ) / (π/2)` spreads them across the body. **The ramp is interpolated by hand between texels** (`rampColor`), so the same GLSL reads a LINEAR + REPEAT texture under `spikeMeshGpu` and a NEAREST + CLAMP data texture under `noiseFieldGpu` (v4) identically — proven by pixel-identical dumps before and after the switch. **The normal is flipped to face the camera in the fragment** (`if dot( n, v ) < 0`), which is what lets a tunnel wall be seen from inside and spares every sketch a winding convention. The light direction is a `vector3d` in CAMERA space (p5's y-down basis, `yDown: true`); the raymarched v4 rotates its world normal into that basis so the control means the same thing on all four. **How to apply**: a fifth iridescent sketch supplies geometry and an `extra` channel and takes the material whole; a new colour look is a new ramp, not a new shader.

2026-10-09 — `utils/spikeMeshGpu.js` is the peaks family as SOLID surfaces: the envelope of a disc stack is a surface of revolution (radius = the stroke-weight curve, axial position = the depth-easing curve), so one canonical (t, angle) grid is drawn instanced per (col, row) cell, placed by the sketch's own `computeSpike` GLSL — the same Perlin table, `mapEase` and p5 default camera as `peaksFieldGpu.js`, which now exports them — with hemispherical tip and base caps and normals from finite differences of the same surface function; a `bodyPoint( t, a )` surface is drawn once underneath. v1 / v2 / v3 keep peaks-sphere / -cylinder / -tunnel's placement and option names (`layers` / `lod` / the rainbow are gone: a surface has no discretisation). Three traps. **Pixel units come from the layout, the buffer from the supersample**: p5's offscreen WEBGL buffers have no MSAA, so the mesh is drawn at `rendering.supersample` × and composited down, and the projection must be computed from `p.width / p.height`, not the buffer, or everything halves. **A base cap is a shallow dome, not a hemisphere** (`profile.baseCapDepth`, 0.5): a hemisphere wider than the body it sits on comes out the other side. **Solid spikes intersect where discs merely overlapped**: 14 arms 194 px wide on a 81 px cylinder meet along their whole length and the shading seams read as a jagged crown, so the first defaults shipped fewer, thinner spikes than the originals — the originals' numbers are not the right defaults for a surface. The maintainer then retuned all four in the studio (2026-10-09) and the direction is the taste signal: NEEDLES over a small body — tips at 0.5–1 px, more and longer spikes (sphere 38 meridians × 311 px, cylinder 12 × 12, tunnel 41 rings), the body shrunk to 0.5–0.6 of the radius or switched off, finer multi-octave terrain. Propose new defaults in that direction, not back towards fat pills. `flat` is a reserved word in GLSL ES; the bench's fail-closed console check is what caught both that and a duplicated `bodyPoint`. Measured under SwiftShader at 540 × 675 (ratios, not desktop times): see the commit that added the category.

2026-11-10 — **A spike can be a petal: the optional `spikeShape` hook.** `iridescent-v5-spiral-bloom` (a phyllotaxis flower: petal i at i × the divergence angle, `cols = count`, `rows = 1`, so the material's `index` axis IS the spiral) needed blades, not thorns. Rather than a second renderer, `spikeMeshGpu.js` takes an optional `void spikeShape( col, row, dir, out vec3 side, out vec4 form )` in the sketch's GLSL, detected by regex like `bodyPoint`: `side` is the cross-section's first axis, `form` = ( flatten, curl, pinch, cup ) — the second axis's radius ratio, the centreline's circular-arc bend over the length in radians (towards `cross( dir, side )`), a narrowed foot that reopens over 45% of the length, the section's edges lifted. The default hook reproduces the old frame choice and `( 1, 0, 0, 0 )`, and every new term is guarded or multiplies by an exact 1 / adds an exact 0: v1–v3 dumped before and after diff at **0** on every channel — re-run that diff after any edit to `spikePoint` / `spikeProfile`. Normals stay finite differences of the same function, so a shaped spike is lit for free. Three things learned tuning it. **Units are absolute pixels of the 1080 × 1350 layout**: a 540 × 675 bench crops the flower, so judge framing at the real size. **The taper easing decides thorn vs petal** more than any width: `easeOutQuad` gives daggers, `easeInSine` tongues, `linear` with a `easeOutQuart` width and a 0.7 pinch the pointed dahlia petal that shipped. **Every clock is a whole number of cycles of the loop phase** (bloom wave with a heart → rim lag, a ±0.12° breathing of the divergence that visibly winds the arms because it is multiplied by the index, a length ripple, the noise read on a circle); frame 0 vs frame 720 differs on 0.04% of pixels (silhouette edges, float32 clock), frame 720 never being exported. Cost under SwiftShader at 540 × 675: 1389 ms a frame against v1's 2935 on the same dev server (233 instances at 40 × 20 against 380 at 48 × 24). **How to apply**: a new mesh form in this category is a placement plus, if it is not round, a `spikeShape`; the flower's axis is z (it faces the default camera), `rotation.tilt` is its static pitch, and `spinTurns` around y shows its back, where only the receptacle body closes it.

2026-11-10 — **`iridescent-v6-peaks-knot` puts the peaks family on a torus knot** (numbered v7 until the flame left the category), asked for as "the original iridescent aspect" after the flame left it: round needles, the tube as body, the pale ground, the material whole. Columns run along the (p, q) curve and rows around the tube; q = 0 is a plain ring. Rules it taught. **The frame across the curve is the torus's own normal**, not a Frenet frame: the curve lies on a torus whose normal is perpendicular to it everywhere, so the frame closes on itself with no twist to correct. **The terrain is sampled at the needle's foot in space** (`perlinNoise( base / size × scale + offset )`, offset ≥ 20 because p5's Perlin mirrors negative inputs), which has no seam where the curve closes — a (column, row) lookup as on v1 does. **A sketch uniform must not be named `uP` or `uMV`**: they are the renderer's matrices, and the redefinition fails the compile with a matrix-to-float error far from its cause. **The hue runs around the knot through the material's own stagger on `angle`** (weight 1, one cycle, so the ramp meets itself where the angle wraps): the `column` axis would not do, the body's cell being ( around, along ) where a spike's is ( along, around ). **Only whole trips along the curve loop** (`flowTrips`): a shift of one column maps the grid onto itself but not each instance's `cell`, so the stagger would jump. The body's parameters are swapped on purpose — `t` along the curve (220 rings), `a` around the tube (20 segments) — because the renderer caps segments at 128 and a knot needs more along. Framing: major 280 + winding 130 + needles 240 fills 1080 × 1350 once tilted (nominal reach 672 px, more than the half-width, because the knot never faces the camera flat for long). Frame 0 vs 720 differs on 0.7% of pixels by at most 21 levels (1280 needles of supersampled edges), 68% for the next frame. 3527 ms a frame at 540 × 675 under SwiftShader (v1: 2935).

2026-11-10 — **`iridescent-v7-peaks-shell` is the peaks family on a seashell**: one spiral whose radius, drop along the axis and tube width all scale by `exp( growth × ( s − 1 ) )`, so each whorl is the previous one, larger, and the needles take the same factor (`selfSimilar`). What it adds to the knot's rules. **An OPEN curve carries no flow**: instances cannot travel along it without popping at the mouth, and a shift by one column would break the material's per-instance `cell` anyway, so what moves is a length wave and a sway wave (the needle's direction leaning along the tangent) running apex → mouth a whole number of cycles per loop, plus the spin; the wave COUNTS need not be whole since nothing wraps. **Needles on the outer arc only** (`coverage` × the circumference around `aim`): the inner side lies against the previous whorl, and needles there read as noise. **Ridges are a whole number per TURN, not per shell** (`cos( TAU × ridges × turns × s )`), which is what lines the long spines up from whorl to whorl into a murex's combs. **Whorls touch when the tube's radii of two neighbours sum to their spacing**: tube × ( 1 + 1/k ) ≈ height × ( 1 − 1/k ) with k = `exp( growth / turns )`; below that it is a spring, not a shell (the first defaults were). **The material's scale is the FULL extent here** (twice the reach, where v1 passes the reach): the position axes then read 0..1 without wrapping, so the apex → mouth stagger on `y` is seamless at any weight. The mouth's tube hangs below the curve's last point, hence the half-tube `translate`. Frame 0 vs 720: 7 of 364 500 pixels, 50% for the next frame; 2987 ms a frame at 540 × 675 under SwiftShader.
