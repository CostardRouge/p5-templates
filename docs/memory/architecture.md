# Architecture

Read before touching the engine abstraction, feature flags, the Next config or anything about what ends up in which bundle.

## Rendering is engine-agnostic on purpose

2026-08-20 — Every rendering back-end implements one interface, `SketchEngine` in `src/engines/types.ts`, and the studio route and the recording pipeline only ever talk to that interface. p5.js, GSAP and Three.js are peers, not a primary plus experiments. The contract covers lifecycle (`init` / `destroy`), playback, a typed event map (`ready`, `frame`, `complete`, `error`, `performance`) and deterministic capture. **How to apply**: adding a rendering back-end means implementing `SketchEngine` and registering it in `src/engines/registry.ts` — never special-casing an engine inside the studio page or the recorder. Read `types.ts` before anything else in this area; it is the file the rest of the system is written against.

## Deterministic capture is a design constraint, not a feature

2026-08-20 — The same sketch must produce the same frames in the live preview and in headless capture, otherwise a recording does not match what the user tweaked. That is why the engine interface exposes `beginDeterministicCapture` / `seekAndDraw` / `captureFrame` (`src/engines/recording/`) and why sketches receive a duration-scaled loop clock rather than raw elapsed time. **How to apply**: never drive a sketch's animation from `Date.now()`, `millis()` or frame counters — take the `time` argument. A sketch that reads wall-clock time renders correctly in the browser and wrongly in an export, and nothing in CI will catch it.

## Feature flags are compile-time and default off

2026-08-20 — `next.config.ts` maps five plain env vars onto `NEXT_PUBLIC_*` build flags: `BACKEND_RECORDING`, `NOTIFICATIONS`, `LIVE_THUMBNAIL`, `PREVIEW_ON_HOVER`, `INTERACTION_BINDINGS`. All default off, and `NEXT_PUBLIC_*` values are **baked in at build time**, not read at runtime. **How to apply**: changing a flag means rebuilding — restarting the server is not enough. Toggling one in a running dev server and seeing no effect is expected behaviour, not a bug. The Dockerfile takes the same names as `ARG`s, and the CI build job sets them explicitly (with `INTERACTION_BINDINGS: "true"` so that code path is compiled) — mirror those when reproducing a build failure.

## Server-only dependencies are declared external

2026-08-20 — `serverExternalPackages` in `next.config.ts` lists `@aws-sdk/s3-request-presigner`, `archiver`, `tar`, `bullmq`, `ioredis` and `web-push`: Node-only modules that must never reach the browser and that Turbopack should not parse into the module graph on every server compile. Next already ships `@aws-sdk/client-s3`, `sharp`, `prisma` and `playwright` in its own default external list, so only the uncovered ones are named here. The omissions are deliberate: `mediabunny` and `gif.js` power **client-side** recording and must stay bundled. **How to apply**: before adding to that array, check `node_modules/next/dist/lib/server-external-packages.json` — duplicating Next's list is noise. Never add a package the browser needs.

## The `/embed` route is deliberately framable

2026-08-20 — Every route keeps the browser's default same-origin framing except `/embed/:path*`, which `next.config.ts` serves with a `frame-ancestors` CSP. It defaults to `*` so a fresh install works as a public widget; `EMBED_FRAME_ANCESTORS` (space-separated origins) narrows it. **How to apply**: this is the one place where relaxing a security header is intended — do not "fix" it. Restricting it is a deployment decision made through the env var, not a code change.

## Persistence chain, and a rename done without SQL

2026-08-20 — `prisma/schema.prisma` holds `Preset` → `PresetSnapshot` → `Job` (plus `PushSubscription`). A preset is the mutable named configuration, a snapshot freezes its options, a job renders one. The models were renamed from `Template`/`TemplateSnapshot` but keep `@@map("Template")` and `@map("templateId")`, so the rename cost no migration and the database columns still say "template". **How to apply**: expect the old names in SQL, in migration files and in stored job paths; do not "clean them up" into a migration. The Prisma client is generated to `src/generated/prisma` (gitignored) — run `npx prisma generate` after pulling a schema change, or `npm install`, which does it via `postinstall`.

## Analytics is self-hosted Umami, tracked by hand

2026-08-23 — Google Analytics was replaced by a self-hosted, cookieless Umami instance (`src/lib/analytics/umami.ts`, `docs/analytics.md` for the full contract). Two choices are load-bearing and look like mistakes if you do not know why. **`data-auto-track="false"`**: Next navigates without reloading the document, so Umami's auto-tracking records one pageview per tab, or records later views carrying the previous page's title — `UmamiTracker` sends every view by hand from `usePathname()`/`useSearchParams()`, chaining the previous in-app URL as the referrer so internal pages are not all credited to the external source that opened the tab. **The pageview queue**: `strategy="afterInteractive"` injects the script *after* hydration, so the tracker's first effect runs before `window.umami` exists; an optimistic `window.umami?.track(…)` silently drops the initial view of every cold load. Queue when absent, drain in the script's `onLoad`. **How to apply**: never "simplify" either of those away, and never paper over the race with a `setTimeout` — it moves the race, it does not remove it. The config values are `NEXT_PUBLIC_*`, hence baked in at build time (see the feature-flag entry above) and declared as Docker `ARG`s; unlike the other `NEXT_PUBLIC_*` args they are deliberately not empty-defaulted, because an empty website id is the documented kill switch and would ship every image with analytics off.

## Asset loading is one reported step registry, and `ready` is not gated on it

2026-08-31 — Every asset load (images, fonts, audio, video, the p5 library and the sketch module) opens a *loading step* in `src/lib/assets/loadingProgress.ts`. A step is registered with `pendingMedia` on open and settles on load or failure, so deterministic capture now waits on images and fonts too — before this, only video seeks and audio gated it, and `awaitPendingMedia` had no caller at all. `P5Engine` resets the registry on `init()` and re-emits every snapshot as the `loading` engine event, which the sketch page's placeholder renders as `n / m assets` plus the in-flight labels. **How to apply**: load p5 assets through `@/p5/utils/assetLoaders.js` (`loadImageAsset` / `loadFontAsset`) rather than calling `getP5().loadImage/loadFont` directly, and report any other async work with `beginLoadingStep` / `reportAssetLoading` — that public API is the seam for sketch-defined loading operations. Two traps: p5's **failure callback is load-bearing** (without one p5 never decrements its preload counter, so one stale S3 path hangs the sketch on the loading screen forever), which is why the wrappers always register one and no call site may skip it; their second parameter is an **options object** (`{ label, onError }`), and passing a bare string there fails *silently* — destructuring a string just yields undefined properties, so the label quietly falls back to the filename instead of throwing; and `resetLoadingProgress()` must release still-pending steps, otherwise a sketch switch leaves orphaned promises that wedge the capture gate permanently. Deliberately **not** done: the engine's `ready` event is still fired on first draw and is *not* gated on assets settling — the `TODO.md` "Loading & Asset System" entries ask for that, but gating re-introduces the exact hang class the failure callbacks exist to prevent, so it needs a timeout/failure policy decided first.


## The sketch loading screen holds the poster still, by construction

2026-09-01 — The loading screen (`src/components/SketchPage/SketchLoadingPlaceholder.tsx`) reads progress off `loadingProgress.progress`: the poster loads dimmed and is revealed left-to-right, a 4px bar rides its bottom edge, and one caption names the asset in flight. **Only the poster box carries height** — the reveal layer, the bar and the caption are all absolutely positioned, and the caption sits in a fixed `h-4 overflow-hidden` slot. That is not styling preference: the previous version put telemetry *in flow* inside a vertically-centred column, so every line it added re-centred the stack and visibly shifted the thumbnail. **How to apply**: never add an in-flow element to that column; if something new must appear, position it out of flow or give it a reserved fixed height, and re-run the headless check that asserts the poster's `getBoundingClientRect()` is identical across every loading frame (`[data-loading-reveal]` / `[data-loading-fill]` are stable hooks kept for exactly that). Three traps, all paid for: the poster box needs an explicit `aspect-ratio` from the sketch size, because a bare `h-auto` image is 0px tall until it decodes and then snaps to full height — a shift of the very element being held still; the clipped copy inside the reveal needs a fixed `w-60 max-w-none` (a relative width squashes it as the wrapper grows instead of revealing slices) plus the same `onError` fallback and `data-pin-nopin` as the base, since it is a second cover image; and the edge bar deliberately does **not** use `--progress-start/--progress-end` — those greys are tuned against the page background and disappear over a photograph, so it uses a translucent scrim with a `foreground`-toned fill. Progress is displayed monotonic and the screen only mounts after ~150ms (`useDelayedFlag`), so cached loads show nothing rather than flashing.

## A sketch can run inside another sketch, through three swaps

2026-08-31 — The `sketch` content item (`SketchLayerItemSchema`) embeds a whole other p5 sketch as a layer, beside text, images and the HUD elements. Nothing about it is special-cased inside sketches: it works because three module singletons can be pointed somewhere else for the duration of the embedded draw, and the whole runtime follows.

- **The surface** — `getP5()` is the only way sketch code and every helper under `@/p5/utils/` reach the drawing surface, so `pushSurfaceOverride( buffer )` (`sketch.js`) redirects a whole sketch, and all the shared helpers it calls, into a `createGraphics` buffer. `p.width`/`p.height` follow the buffer, which is why an embedded sketch *lays itself out* for the layer's box rather than being a scaled screenshot of its own page. `sketch.getCanvasCenter()` reads the override's renderer, or a WEBGL layer gets the host's 2D centre.
- **The parameters** — `pushOptionsOverride( { sketch, size } )` (`options.js`) makes `options.sketch` return the layer's own `settings`. Only those two keys: assets, slides and the clock stay the host's.
- **The registration** — a sketch module registers its callbacks as an *import side effect* onto the shared `sketch` singleton, so importing one mid-run would overwrite the host's own draw. `beginSketchCapture()` redirects the two setters into a capture object; the result is remembered per path in `sketchFnCache.js`, **which `P5Engine` must share** (ES modules evaluate once, so a sketch the page already imported registers nothing on a second import — with two caches that case silently ran the host's functions in the layer).

Rules that fall out of it, all in `nestedSketch.js` / `drawSlideSketch.js`:

- **The clock is never swapped.** An embedded sketch reads the host's loop phase, so the composition stays a pure function of the frame index and headless capture reproduces it. The per-layer `framerate` is therefore counted in loop time (`redrawStep`), not wall-clock: a 6 fps layer drops the same frames in the export as in the preview.
- **`background()` is intercepted, not filtered.** "Draw its own background" has to hold whether the sketch paints from a `backgroundColor` option, a hard-coded colour or a palette lookup, and the call is where all three meet — so the buffer proxy returns a no-op for it. Off by default, or every embedded sketch is an opaque rectangle.
- **The buffer proxy falls through to the host.** `p5.Graphics` carries every `p5.prototype` method bound to itself, but not the p5 *instance* properties (`frameCount`, `mouseX`, key state); those resolve on the host, which is also the honest answer.
- **Some methods go the other way — present on the buffer, and broken there.** `p5.Graphics` also copies the methods that only mean anything on a real instance: `createGraphics` ends in `pInst._elements.push( … )`, and a Graphics has no `_elements`, so *every GPU-helper sketch* (`peaksFieldGpu`, `noiseFieldGpu`, `glowBatchGpu` — they all go through `graphics.createAutoResizableGraphics`) died with "Cannot read properties of undefined (reading 'push')". `HOST_METHODS` in `nestedSketch.js` routes those to the host: the loaders, the DOM element factories, `createGraphics`. The test for membership is "needs instance state AND produces something renderer-independent" — `createShader` / `loadShader` / `createFramebuffer` / `createCamera` must stay on the buffer, or they belong to the wrong GL context, and `createCanvas` must never be forwarded (it would replace the page's canvas). **How to apply**: a layer that crashes on an undefined instance field is a missing entry in that set, not a broken sketch.
- **`createAutoResizableGraphics` does not auto-resize inside a layer** (`graphics.js` checks `getSurfaceOverride()`). Its handler resizes to the *host* canvas, which is not the layer's size, and it would outlive the embedded run — `events.registeredEvents` is only cleared between sketches, so one would pile up per re-setup. Nothing is lost: a layer's buffer size change tears the instance down and re-runs setup.
- **A sketch's module-level state is shared between the page and its layers.** The GPU helpers cache a buffer at module scope keyed on `state.p5Ref !== p`; the proxy is a distinct object per layer, so host and layer thrash each other's cache rather than corrupting it — correct but slow when the same GPU sketch runs in both places at once.
- **`p5.Graphics` does not reset between frames** the way the main canvas does — hence `buffer.reset()` before each draw, or a sketch that translates once per frame walks off its own buffer.
- **A WEBGL host needs `resetMatrix()`, not just the origin translate.** A layer is one textured quad, so it inherits whatever transform the host's draw left standing; a 3D sketch that rotates the world and does not pop sweeps the layer into its scene. Verified on `36days-of-type-2023-0`: the layer went from foreshortened-into-the-floor to a flat, axis-aligned overlay. (A host that moves the *camera* still carries the layer — `resetMatrix` restores the view matrix, not the camera.)
- **A draw that suspends mid-frame cannot be embedded — so none of them do any more.** The swaps are module globals: they hold for exactly as long as the embedded draw runs *synchronously*. A `sketch.draw( async () => … )` that awaits mid-frame returns a pending promise, the swaps are restored, and its continuation resumes reading the HOST's surface and parameters — painting the rest of itself onto the page's canvas, usually after throwing on `options.sketch.<its own key>`. **Holding the swaps across the await is not the fix**: `freeLayout` goes straight on to the next content item in the same frame, so it would corrupt every layer drawn after this one instead. This affected 38 of 301 p5 sketches, and the cause turned out to be one keyword — `grid.create` was declared `async` and never awaited anything, so `grid.draw` / `grid.prepare` / `gridMask.field` awaited it, and 38 draws inherited `async` for nothing. De-asyncing that family made all 38 synchronous and embeddable, with no change to the layer runtime. **How to apply**: an `async` helper that never awaits is not free — it makes every caller's draw suspend, which costs embedding and leaves the engine reading the canvas before the frame is finished. And `await` on a non-promise still yields to the microtask queue, so dropping `async` from a helper is only half of it: the callers must drop their `await` too. Note `grid.create` is mocked in `gridMask.test.ts` with `mockReturnValue`, not `mockResolvedValue`.
- **The async-draw guard is kept even though nothing trips it.** `isAsyncDraw` (an `AsyncFunction` check on the captured `drawFn`, before the first call, so no half-frame ever reaches the host) parks the sketch in `failed`; a thenable return is caught as a backstop and its rejection swallowed, since it otherwise arrives as a runtime overlay pointing deep inside the embedded sketch with no hint a layer is involved. `scripts/watch-sketches.mjs` records `asyncDraw` in `metadata.json` (read off the entry file's source, because the picker must know *before* importing anything) and the picker greys those tiles out, offered-but-disabled rather than hidden. The flag is 0 across the catalogue today; all of it exists so the *next* async draw is a greyed tile with a reason instead of a crash. `sketches.test.ts`'s drift check keeps the flag honest for free.
- **Async *setup* is fine** and stays supported: the overrides cover its synchronous head, and setups await loads then draw through the `p` they were handed, which stays the proxy.
- Embedding is one level deep (`getSurfaceOverride()` guards the recursion), buffers are swept when a layer stops drawing, and `sketch.reset()` frees them all through a disposer `nestedSketch.js` registers **on first render** — a module-scope registration deadlocks on the real import cycle (`sketch.js` → slides → freeLayout → drawSlideSketch → here).
