# Backgrounds — read before touching `utils/background.js`, `utils/backgroundSpec.js`, the `background` field or a sketch's `backgroundColor`

## A background is a colour OR a gradient, and the colour stays an array

2026-10-13 — **One `background` field kind (`ControlledBackgroundInput`) replaces the colour picker for a sketch's background**: Solid / Linear / Radial, two colours, strength, easing, and a motion over the loop (Rotate, Drift, Breathe) in whole cycles. The maintainer validated the design (session artifact "Background control") with three calls: **strength** is how far the gradient travels toward the second colour (0 = the first colour flat, 1 = reaches the second), not a contrast around a midpoint; **"Palette paper"** supplies the two colours only — kind, angle, centre, strength, easing and motion stay the sketch's; the three motions are enough (no conic kind). **The stored value stays the saved colour ARRAY until the kind is changed** — every default and every saved document is an array, and an array is painted by the very same `background( ...colour )` call — so switching a field from `color` to `background` moves no published pixel. Only a kind change writes an object (`backgroundFromColor`: the colour as `from`, `to` lifted 30% toward white, or toward black on a light colour).

**Runtime contract** — `resolveBackground( value, { fallback, palette } )` returns a colour ARRAY in every case (the stored array itself for a plain colour; the first stop, or the paper's top, for a gradient) carrying the gradient on a `spec` property; `paintBackground( resolved, target? )` paints it. **Why an array**: about a third of the sketches reuse their background colour elsewhere (`fill( ...bg )`, masks, a GPU uniform), and a call site a migration misses then still paints the first colour instead of throwing on an object spread. P2D fills the canvas's own gradient under an identity transform (as p5's `background()` does); WEBGL clears with `background()` then lays a 2D buffer over the frame with `depthMask( false )` — a textured quad at z = 0 writing depth would hide everything drawn behind it. Never `noTint()` before that `image()` in WEBGL: p5 1.11 stores a null tint and `_drawImmediateFill` throws on it (`.slice` of null) — `tint( 255 )` inside the push/pop is the neutral one. Motion reads `animation.progression`, so capture is deterministic and an export loops. Stops go through `target.color()`, so the gradient reads its arrays the way `background()` does (colour mode included).

**The control** composes the studio's own fields: everything below the kind (`from`, `to`, `angle`, `center`, `radius`, `strength`, `easing`, `motion`, `cycles`) is a `FieldRenderer` on a path inside the value (`backgroundColor.angle`…), passed in as `renderField` to avoid a circular import — so each number binds to a knob / LFO / audio and gets the driven look. While the value is an array, its colour is a `FieldRenderer` on the field's own path (the old colour binding keeps working). `palette: "<path>"` on the field config (relative to the field's parent, like the palette picker's `custom` paths: `colors/palette`, `../colors/palette` from a `scene` group) offers the "Palette paper" source; a house function (`HOUSE_PALETTE_IDS`) has no paper, so its sketch keeps its own colours and the control says so. This replaced step 3's "use the palette's background" checkbox on the 2D sketches (`housePaletteBackground` and `paletteBackgroundField` are gone).

**Scope (2026-10-13)**: 212 2D sketches plus the 47 shader sketches (step 5) paint through `paintBackground`, their field switched (`backgroundColor`, pulse's `background.color`, text-mask's `background`, sculpt v5–v9's shared `backgroundColorFormConfiguration`, a few nested ones); `shaderPaletteBackground` and the shader checkbox are gone. Left on the plain colour, on purpose: noise-grid v1 (its GPU renderer paints the background itself), and ~37 photo / webcam sketches whose colour is reused in ways a codemod should not guess (photo-*, hand-tracking-*, text-dice). **How to apply**: a new sketch reads `resolveBackground( … )` once per frame and paints with `paintBackground`; a sketch that wants the colour elsewhere spreads the resolved array, never the stored value.

2026-10-13 — **Trap: a value that changes SHAPE (array → object) must be replaced, never merged.** `deepMerge` (`p5/shared/utils.js`, the `/embed` delta merge — and so `scripts/bench-sketch.mjs`, which renders through `/embed`) merged a `{ kind, from, … }` delta into the default `[r, g, b]` as an array with keys bolted on: the gradient was silently painted as the plain colour, in every bench and on every shared link. It now replaces an array with an object whole (`shared/__tests__/deepMerge.test.ts`). The studio's live store (`mergeChangedInPlace`) and the per-slide merge (shallow) were already right. Any new composite field whose stored shape can change needs the same check on every merge path.

## Shaders: most need nothing, four read the gradient in GLSL

2026-10-13 — **A shader sketch takes the gradient in one of three ways, decided by where its background is drawn.** (1) Most (braid, rings, sculpt, flip, flowers-shaders, signals, noise-grid v5–v12) render a buffer that is TRANSPARENT where nothing is hit and composite it over the 2D canvas: painting the 2D background with `paintBackground` is all they need. (2) The `noiseFieldGpu` dot renders (noise-grid v2 / v8, torsade-shaders v2) clear their buffer to an OPAQUE `background`: with a gradient they pass `alphaOver: true`, which clears to transparent BLACK and blends alpha as one / one-minus-src-alpha. **Trap**: the canvas reads the GL buffer as PREMULTIPLIED, so `clearAlpha: 0` alone is wrong twice — the clear keeps the background's RGB under alpha 0 (rgb > a, which the compositor ADDS over everything beneath: a cream gradient clipped to pure 255 white), and the plain blend squares a dot's alpha. Check a "transparent" GL buffer by sampling pixels (`convert … %[pixel:p{x,y}]`) against the expected stop, not by eye. It is opt-in because torsade-shaders v3 already used `clearAlpha: 0` over its glow with a plain colour and that look must not move; it takes `alphaOver` only when a gradient is set. (3) Shaders that paint the background THEMSELVES — dragon-corridor v1–v3 (a missed ray and the fog fade into it) and shader-loops (the vignette) — include `BACKGROUND_GLSL` (`utils/backgroundGlsl.js`) and call `backgroundAt( uv with y down )`; `backgroundUniforms( resolved, { width, height } )` hands them the same 25 stops and geometry the 2D painter lays (a plain colour fills every stop, so the old colour comes back exactly). `resolveBackground`'s `own` option keeps shader-loops' own "iridescent" (its cosine) from borrowing the shared preset's paper. Verified: defaults pixel-identical on 15 shader sketches of every family; the gradient shows wherever a sketch leaves its background visible (sketches that cover their frame — noise-grid v11 at its defaults, torsade v7 — show it only in the gaps).
