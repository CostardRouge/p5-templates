# Transitions — the sequence item and the scene cut

Read before touching `src/sketches/p5/utils/sequence/` (the timeline, the GLSL catalogue, the compositor, the plate / splash / loader painters), `slides/common/drawSlideSequence.js`, `slides/common/drawSceneCut.js`, the `sequence` entries of `field-config.ts`, `SceneCutSettings`, or before adding a transition kind or a scene kind.

## A transition between whole sketches is a content item, not a slide mode

2026-10-19 — The ask was to cut from one entire sketch to another, with cinema: camera moves, overlays, splash and loading screens. A slide is the parameters of ONE host sketch, the montage (`slides/morph/`) interpolates those parameters and cannot draw two sketches at once, and the engine renders one slide per frame — so a transition BETWEEN slides would need two slides rendered per frame, which nothing supports. The only thing in the runtime that runs a different sketch is the sketch layer (`nestedSketch.js`), so the `sequence` content item owns its scenes: a sketch scene is a sketch layer under another name (a synthetic layer item through `renderNestedSketchLayer`, keyed `<layer key>:scene:<n>`, so it gets the buffer, the three swaps, the load queue and the async-draw refusal for free), and the generated scenes (splash, loader, plate) paint into a P2D buffer of their own (`sceneCanvas.js`). **How to apply**: a new scene kind that draws something is a painter in `sequence/<kind>.js` taking `( g, scene, width, height, env )` in LAYOUT units (the buffer may hold more or fewer pixels; `drawSlideSequence` scales) and touching nothing global; a scene that is another runtime (video, a DOM engine) is not this item — it would need its own buffer source.

## The clock

2026-10-19 — `timeline.js` (pure, tested): scenes share the host loop in proportion to `weight`, back to back; a scene ENTERS over the first `transition.duration` seconds of its own slot while the outgoing scene keeps drawing under it, its own clock running past its slot; the entrance is clamped to `min( own slot, previous slot )` so at most two scenes are ever on screen; `cyclic` makes the first scene enter from the last across the loop boundary (what closes the loop), `once` holds the last. A sketch scene's phase is `loops` turns over its slot from `progression`, handed to the layer runtime as the `progression` OFFSET `wrap( scenePhase − wrap( hostPhase ) )`, because `layerPhase` adds the offset to the host phase and reads 0 as "follow the host" (`loops: 0`). **Trap**: `time.phase()` is unwrapped during capture (it climbs past 1) — every sequence computation wraps it first, or the preview and the export disagree past the first loop.

## One shader pass per transition kind

2026-10-19 — `transitionGlsl.js` has two families. A FIELD kind defines `float field( vec2 uv )`, the progress at which a pixel is revealed; the prelude turns it into the mask (softness, remapped so 0 reveals nothing and 1 everything whatever the softness) and lays the edge light along the frontier. A WARP kind defines `vec4 transition( vec2 uv )` itself (push, zoom, swirl, cube, glitch, tiles…). The two cameras (`cam()`, zoom about the centre, roll in pixel space, pan) and the film grade run in the same pass, so a sequence is ONE fragment program per frame; when nothing transitions and no camera or grade is active, the scene buffer is blitted directly and no GL pass runs. The kind is baked into the program (one program per kind per record), never branched on with a uniform — the SwiftShader lesson in `sketches.md`. uv is y-DOWN like a canvas: row 0 of an uploaded canvas is the top of the picture. The edge light reads a palette ramp (`plate.js` `paletteRamp`: the `shaderPalette` bake, uploaded once per id on unit 2) at `progress + distance`, or the block's colour when `palette` is the `"color"` sentinel; a stale palette id draws the colour. Effect parameters travel through eight generic uniforms (`uCenter`, `uAngle`, `uSoftness`, `uCount`, `uCount2`, `uAmount`, `uSeed`, `uMode`) that `effectUniforms()` fills from the effect's fields. **How to apply — adding a kind touches four places and `sequenceItem.test.ts` checks all four**: a branch of `SequenceEffectSchema` with an explicit `default` on EVERY field (a conditional-group switch rebuilds the object from them, `sketches.md`), a form branch in `sequenceEffectConfigs`, a GLSL body in `TRANSITION_BODIES`, a case in `effectUniforms`.

## The compositor owns a GL context per sequence

2026-10-19 — `compositor.js` keeps one WEBGL `p5.Graphics` per item key — programs, the quad and the three textures belong to THAT context and are never shared between sequences; the scene canvases are uploaded as textures every frame with `texImage2D( canvas )` (a P2D or a WEBGL graphics' element both work, as p5's own `image( graphics )` relies on), `UNPACK_PREMULTIPLY_ALPHA_WEBGL` set off on every upload because p5 leaves it on. Records are swept after 180 idle frames (the sketch-layer rule) and dropped on `sketch.reset()` through `sketch.disposeSequences`, installed lazily on first render for the same import-cycle reason as `disposeNestedSketches`. Raw WebGL rather than `p5.Shader`, like the other GPU helpers: `setUniform` re-looks every name up and re-wraps every texture per call.

## The scene cut

2026-10-19 — `SceneCutSchema` on a slide and on the root (`slide.cut ?? options.cut`): the loop opens out of a plate over `in.duration` and closes into it over `out.duration` (each capped at half the loop), through the same catalogue, drawn LAST in the slide post-draw by reading the host canvas itself as the `from` / `to` texture (`drawSceneCut.js`, one record `"scene-cut"`); the plate drifts over the whole loop so an exit lands on the colours the next entrance starts from. The combined multi-slide export still joins slides as hard cuts underneath (`recording.md`), but each slide's out + in now reads as a film cut. The block is optional and absent until the panel's switch parses it in whole (the montage precedent). **Trap**: under zod 4 an `.optional()` key whose schema carries `.prefault( {} )` is MATERIALISED on every parse — `SceneCutSchema` has no prefault of its own for exactly that reason (`sceneCut.test.ts` pins the absence).

2026-10-20 — **The exit follows the entrance** (`outFollows`: `"rewind"` default, `"same"`, `"own"`; `outOwnDuration` keeps `out.duration` while following). The maintainer chose it from four mechanisms built live and bound to one cut (a follow select, a chain toggle, per-field inheritance, copy / swap buttons): the select won because it is one key and one gesture; per-field inheritance was rejected as a second state on every field and a partial block every reader must merge; copy buttons because a copy diverges at the next edit and, above all, a REWIND is not expressible as settings — an iris that closes, blinds that close, have no `out` value — so the link has to live in the data. Precedent: `motion-foley`'s per-gesture release select, `"↺ Reverse (matched)"` by default. A rewound exit is the entrance with its progress run 1 → 0 and its easing reversed in time (`mix = ease( 1 - raw )`, plate → picture); `resolveSceneCut` flags it `rewind: true` and `drawSceneCut` only swaps from / to. `sceneCutExit( cut )` is the one place that says which spec and which length the exit plays; a block without `outFollows` reads as `"own"` (the shape before the link). While following, the panel folds `out` to a summary, the own-duration switch and slider, and "Detach", which copies `in` into `out` (keeping an own length) and sets `"own"` — from rewind the copy then plays forward, by construction.

## The form

2026-10-19 — The scenes are an `item-list` whose row is a `conditional-group` on `kind`, with `schema: SequenceSceneSchema` so a new row and a kind switch are whole default scenes — `ItemListRenderer.getDefaultValueForConfig` learned the `conditional-group` case for it (it used to add `""`), and `headerShowsValue` names the variant in a shut row ("Scene · Splash"). `ConditionalGroupConfig.schema` is typed `ZodType` so a `.default()`-wrapped union is accepted without the `@ts-expect-error`s the specs groups carried. A sketch scene's parameters come through the new `sketch-settings` component — `EmbeddedSketchFields` over the field's parent path — beside a `sketch-picker`, which writes the sibling `settings`. The "Sequence" palette tile picks a sketch first, like "Sketch", and seeds a splash card named after it cutting into it (`sequenceSeedFor`), so the system is visible the moment the layer lands. The cut is edited in the content rail's `transition` band for the root too (`SceneCutSettings`, generic `FieldRenderer` over `sceneCutFieldConfigs` at depth 1); the montage stays slide-only. A splash headline wider than its frame is shrunk to fit (asked `size` × 0.92 width / widest line) — the first render at 540 px lost its first and last letters.

## Verified, and what is not

2026-10-19 — Headless (Playwright + SwiftShader, production build, the document handed over through the `sketchbook:pending-import` sessionStorage key with `name` = the sketch name): a voronoi host with a four-scene reel (splash → background-grid sketch → loader → plate, iris / wipe / glitch / tiles entrances, palette edge lights, push-in camera, letterbox + vignette + grain) and the cut on; frames rendered through `window.__sketchCapture` at 0.3 / 1.0 / 1.83 / 3.2 / 4.4 / 5.2 / 5.5 s of a 6 s loop: seven distinct frames, the same frame twice byte-identical, zero console errors, and the PNGs read as intended. Not done: nothing measured on a phone; no WEBGL embedded scene exercised (the `texImage2D( webglCanvas )` path rests on p5's precedent); the cut sound (the montage scheduler reused per item, `sequenceSound.js`) not heard live; the slide 0 ↔ 1 boundary does not carry `cut` (nor `transition`); a scene's words arrive one frame after its plate (fonts load asynchronously, `string.fonts`); a lower-third OVER a scene is not a scene kind — a text item on the slide draws over the whole reel; the picker's "Own colours" tile is a neutral swatch (the palette picker cannot show one live colour).
