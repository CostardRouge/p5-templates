# Agent commands — the registry and the MCP server

Read when you touch `scripts/mcp/`, add a command an agent can call, or change a route or page contract those commands lean on (`/embed`, `/api/sketches/form`, `/api/recordings/*`, `window.__sketchCapture`).

## One registry, same shapes as Atelier and Winnow (2026-10-09)

**Decision.** The maintainer wants Claude (or any MCP client) to drive Sketchbook, on the conventions Atelier set the same day (`CostardRouge/atelier`, `src/shared/commands/registry.ts`, after LightCraft's `engine.execute`): every verb is a COMMAND `{ id, title, description, params, available, run }`, ids dotted and stable, run through one `execute` that checks the params first. Params are the same small subset (`number` with `min`/`max`/`integer`, `string` with `enum`, `boolean`, `strings`, `object`), turned into JSON Schema by `paramsJsonSchema`; out of range is REFUSED, never clamped; an unknown key is refused naming the known ones; `available()` answers `true` or the REASON; errors are coded `unknown | unavailable | invalid | failed`; a picture to look at is an `ImageResult` (`kind: "image"`, base64, no `data:` prefix). **Why**: an agent moving between the three projects meets one listing, one error vocabulary and one image shape. **How to apply**: keep `scripts/mcp/registry.ts` in step with Atelier's file; two deliberate differences, both because commands here reach a server over HTTP instead of a mounted screen — `available()` may be async (so `list()` is), and there is no per-screen registration stack nor `waitFor`.

## The code runs from source through Node's type stripping (2026-10-09)

`scripts/mcp/` is TypeScript run as-is by Node ≥ 22.18 (type stripping unflagged; CI and the Docker image are Node 24): a nested `package.json` makes the folder ESM, imports carry their `.ts` extension (`allowImportingTsExtensions` in the root `tsconfig.json`, legal because it is `noEmit`), type-only imports say `type`, and nothing there may use a path alias, an `enum`, a namespace or a parameter property — Node strips types, it does not compile. **Why**: one language with the app, checked by `npm run typecheck` and tested by Jest beside the logic, with no build step and no new dependency (Atelier's server is a zero-dependency `.mjs`; the same spirit). Jest compiles these files to CommonJS through ts-jest, which is fine because it only resolves the relative `.ts` imports. **How to apply**: never import from `src/` there — those files use aliases and would fail under Node; reach the app over HTTP or through the page instead.

## The command set, and which door each one uses (2026-10-09)

Sixteen commands in four files (`scripts/mcp/commands.ts` assembles them; `context.ts` holds the shared HTTP helpers and probes): `app.status`, `sketches.list`, `sketches.describe`, `options.schema`; `render.frame`, `render.stills`, `render.video`; `jobs.get`, `jobs.wait`, `jobs.result`, `jobs.list`, `jobs.cancel`; `drafts.create`, `drafts.update`, `drafts.get`, `drafts.copy`. **Decision: no new server code path for an action** — each command calls what a person's gesture calls: the catalogue is the checkout's `src/sketches/metadata.json`; parameters come from `GET /api/sketches/form`; a document is checked by `POST /api/options/validate` (the only routes added, both pure — `security.md`); a draft is the studio's Save draft (`POST /api/recordings/enqueue`, `status=draft`, files as `file[global][<kind>]`); a frame is the recorder's capture protocol driven from headless Chromium in the MCP process (`frameRenderer.ts`, the `bench-sketch.mjs` recipe); a video is the recording pipeline, followed and fetched through the dashboard's routes. **Why**: there is no auth (`security.md`), so a server-side "render" route would be a public Chromium launcher on the NAS; this way the MCP server adds no attack surface, works against `npm run dev` or the deployment alike, and an agent's request is validated by the very code that validates a person's. **How to apply**:
- A sketch's id is its route tail `<engine>/<category>/<name>` (also its `/embed` and `/sketches` URL); a bare name resolves when unique — two names exist in two engines.
- `options` is a nested DELTA over `formValues`, checked against the controls (`sketchForm.ts`): slider/number ranges, select values, booleans, colours as 3–4 channels 0–255, pad axes (with `field-config.ts`'s defaults: ±1, per-axis overrides), conditional groups against the branch they land on. Images, assets, item lists and device pickers are described but not checked. An unknown key is refused unless the sketch stores it without a control.
- Two ways to make a piece. Quick: `render.frame` / `render.stills` / `render.video` on a `sketch` with a delta, size and clock — rendered on `/embed` (frames) or posted as a queued job (video). Whole: a DRAFT (`drafts.ts`) holds the full document — content items (text, title, image, QR code, HUD, sketch layers), slides, size, clock, the sketch's parameters — and uploaded media; frames render on the draft's own studio page (`/sketches/…?id=<draft>&capturing`, the page the recorder loads), so a still and the video come from the same document.
- Any document a command stores carries the sketch's parameters WHOLE (`formValues` merged with the delta, arrays replaced as the option store does), because the capture page `Object.assign`s the job's options over its defaults; and its other keys as `/api/options/validate` normalises them (below).
- `render.video { draft }` clones the draft (`/api/recordings/<id>/clone`) and starts the copy: a job records once, and the safest default is that the draft stays editable. `drafts.update` refuses anything not in status `draft`; `drafts.copy` makes an editable draft from any job.
- `drafts.update` re-sends every file the draft keeps (fetched back from `/api/s3/<id>/assets/…`): the enqueue route rebuilds `assets` from the files in the request, as the studio's own re-save does. A slide asset whose slide a new `slides` list removed is dropped and reported.
- Uploaded media are referenced as `global/<images|videos|audios>/<name>` (`getScopeAssetPath`); the name is reduced to `[A-Za-z0-9._-]`. `readMedia` reads only media extensions, ≤ 500 MB: an agent could otherwise be talked into uploading any file the user can read to a public server.
- `render.frame` places the frame by `time`, `progress` or `frame`, converted with the page's own clock (`__sketchCapture.timing()`, `recording.md`); a time past the loop is refused, not wrapped. `render.stills` takes `count` positions `from + (to − from)·i/count` (end excluded so a closed loop does not repeat), renders them in ONE page load, saves each PNG and answers a contact sheet.
- An odd width or height is recorded padded to even by the recorder (`recording.md`), so `render.video` no longer refuses it: its answer carries `padded`, one line per size that will change (540 × 675 → 540 × 676), so the agent is not surprised by the file.
- `render.video`, `drafts.*` and `jobs.*` are `unavailable` until `/api/recordings/health` answers (Redis + Postgres + worker; that call also boots the worker), while frames of a sketch still render — a dev server without infra can do half the work.
- A failed job's reason comes from `Job.error` (`recording.md`); against a server older than that column `jobs.get` falls back to the step it died in and says the reason is in the log.
- A page that throws while it loads never becomes ready; the renderer then reports the page's errors instead of a bare timeout.
- Verifying a video needs the infra: `redis-server`, a Postgres with `prisma migrate deploy`, and any S3 — when the MinIO binary is unavailable, `moto_server -p 9000` plus a `PUT /recordings` bucket works, with `S3_ENDPOINT=http://localhost:9000` and any key pair. A sketch that draws at absolute pixel sizes (ping-pong's 186 px ball) does nothing at a small test size — no bounce, no sound — so test sound at the sketch's own size and a low framerate instead.

## The MCP server is a local stdio process with Atelier's three tools (2026-10-09)

`scripts/mcp/sketchbook-mcp.ts` speaks MCP (JSON-RPC 2.0, one message per line) over stdio; `protocol.ts` is the pure handler. Three generic tools, named like Atelier's: `sketchbook_status` (= `app.status`), `sketchbook_commands` (every command, `paramsJsonSchema`, availability and reason), `sketchbook_run` (`{ command, params }` → `execute`). An `ImageResult` becomes an MCP image block followed by its note; a `CommandError` becomes `isError: true` with `"<code>: <message>"`. **Why generic tools rather than one per command**: the registry is the list, so a new command is callable at once, and availability is read when asked rather than frozen at `tools/list`. **Why stdio in the checkout rather than an MCP endpoint inside the app**: no auth (`security.md`) — an HTTP MCP route on the NAS would hand every caller a render queue; the local process reaches the deployment only through routes that are already public. A remote endpoint is the maintainer's call and would need a token first. **How to apply**: stdout is JSON-RPC only — log to stderr; calls run concurrently (a `jobs.wait` must not block a `ping`); one Chromium is kept for the server's life, one context per frame. Configuration is environment only: `SKETCHBOOK_URL`, `SKETCHBOOK_OUTPUT_DIR`, `PW_CHROMIUM`. `claude mcp get sketchbook` reports `√ Connected` on a working install.

## Not done yet (2026-10-09)

- No command writes a preset (the `Preset` model), only drafts and jobs.
- A front-end export (several variants — Reel, square — from one run, GIF, image sequence) has no server equivalent; an agent gets MP4 per slide, and stills through `render.stills`.

## A stored job's options reach the page UNPARSED — store the normalised document (2026-10-09)

The sketch page `Object.assign`s a job's `options.json` over `OptionsSchema.parse( {} )`; the job's own content items, slides and sizes are never run through the schema, so their zod defaults are never filled. The studio never notices because its form writes complete items. A hand-built `{ type: "text", content: "hi" }` therefore reaches the text renderer without `alignment` and throws on every frame (`Cannot read properties of undefined (reading 'horizontal')`) — the page never becomes ready, so a frame render times out and a recording fails at `waitForSelector`. **How to apply**: anything that writes a job's options by hand takes `normalized` from `POST /api/options/validate` (the parsed document, defaults filled) for the keys it supplies, never the raw input. Restrict to the supplied keys: the parse also fills root defaults (1080 × 1350, 60 fps / 12 s) that would override the sketch's own `options.json`.
