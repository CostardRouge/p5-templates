Read when you touch `src/lib/postiz/`, the Publishing dialog, the Export dialog's Publish mode, or the `publish.*` commands.

## The key never reaches the server (2026-11-10)

**Decision.** The API key lives in this browser's `localStorage` (`sketchbook.postiz.v1`, `store.ts`) and the TAB calls Postiz directly (`client.ts`), exactly as Atelier does — even though Sketchbook has a server. **Why**: every route here is public and unauthenticated (`security.md`); a server route holding the key would be an open relay to his Instagram. An agent publishes through the tab too (the studio relay, `agent-commands.md`). **How to apply**: never add an API route that talks to Postiz or stores the key; a file goes from the tab's memory to Postiz, never through MinIO. His Postiz must list this site's origin in its CORS (`https://p5.steeve.website`, `http://localhost:3000` for dev) — Atelier lost a day to a bare network error that was only that.

## `src/lib/postiz/` is Atelier's client, ported, plus several accounts (2026-11-10)

`client.ts` and `rhythm.ts` are copies of Atelier's `src/shared/sources/postiz/` with their specs (Vitest → Jest); every limit there was measured on his instance (Cloudflare's 413 without CORS above 100 MB → `uploadProblem` at 95 MB; Postiz's 10 MB image cap; Instagram's 10-item carousel; captions kept as HTML → `postizText`; 90 posts an hour; no retry nor move in the public API). **A fix to either copy belongs in the other.** What differs: `postBody` takes `entries` — one `POST /posts` with an entry per account, EACH with its own uploaded files, caption and settings (Postiz's own model) — and `channelSettings` fills each network's REQUIRED settings, read from his Postiz's `integrationSchema` on 2026-11-10: Instagram `post_type` / trial / collaborators (Atelier's); TikTok `privacy_level`, `duet`/`stitch` false, `comment` true, `autoAddMusic: "no"`, both brand toggles false, `content_posting_method: "DIRECT_POST"` (UPLOAD would only drop it in the app's inbox), `video_made_with_ai` on videos only; YouTube `title` (2–100) and `type` (public/unlisted/private); read 2026-11-11 when he added them: X `post_type: "post"`, `who_can_reply_post: "everyone"`, `made_with_ai: false` (4 pictures or 1 video, 280 characters), Threads and Bluesky no settings (Threads 500 characters, one video or up to 10 pictures here; Bluesky 300, 4 pictures or 1 video). Any other network is listed and refused (`providerOf` → `other`). Caption limits per network (`CAPTION_LIMIT`) — the shortest of the accounts taking that caption wins (`captionLimit`). His Postiz had two Instagram accounts on 2026-11-10, so `initialDefaults` ticks none until he picks.

**Pure modules**, each with its spec: `postShape.ts` says what a VARIANT can be posted as before it renders (one mp4 → Reel/Post/Story, several files → Carousel, webm/gif or more than 10 files → nothing, with the reason); `caption.ts` fills the template (`{title} {description} {tags} {engine} {seconds} {link} {sketch}`; `sketchTitle` drops the version: `iridescent-v7-peaks-shell` → `Iridescent · Peaks shell`); `publishStore.ts` keeps a sketch's post (variant, kind, accounts, caption, approval, network settings, what it sent) per sketch beside the variant list — never in the document, for the variant store's reason — with the WHEN in memory only (a stored date goes stale); new words take the approval back (`patchedDraft`). `send.ts` is the ONE send path (`routesProblem` before a byte leaves, account by account; `postableFile` turns a PNG into the JPEG Instagram requires — drawn on white, the person's download stays PNG; `sendRoutes` uploads each variant's files ONCE, then one post request with an entry per account, and a second one for the Instagram accounts that also take the file as a story).

## `publish.*`: the agent publishes through the same post (2026-11-10, P5)

Eight commands (`src/lib/agent/commands/publishCommands.ts`) over a `publish` member of `StudioHandles` (the kept connection, a client, the sketch's key in `publishStore`, its caption facts, a variant's slide span, `postableFile`): `publish.status` (accounts, rhythm, next free slot, the post as the band holds it, what this sketch sent), `.facts`, `.compose` (accounts by id, `routes` = `{ accountId: variantId }`, a default `variant`, `kinds` per Instagram account or one `kind`, `stories`, when = `next` · `now` · `draft` · an ISO time WITH its zone, network options — a kind the variant cannot be and an unknown account are REFUSED, never bent), `.caption` (`template` and `short`, new words never approved), `.approve`, `.schedule`, `.calendar`, `.unschedule`. **Rules**: they write the same per-sketch post as the Post band (an agent's choices appear in the dialog) and read it through `planPost`; `.schedule` renders through `h.exports.run` and sends through `sendRoutes`, then remembers each account's format (`h.publish.remember`), so the button and an agent cannot send differently; it is refused until the caption is approved, and `.approve`'s description says to call it only when the person said so in the conversation (Atelier's C4). One send to N accounts is N Postiz posts: `.unschedule` takes back every post of that send (seen live: the first build left TikTok's). Not wrapped specially: `.schedule` is a long run like `export.run`, and like it does not show in the Export dialog's table. The agent guide gained a fourth example prompt and a line in «What can Claude do here?». **Verified** in a live tab through `window.sketchbook.run` against the stub: the eight listed, a Reel refused for a still, compose to two accounts on the next free slot, schedule refused unapproved, then approved and sent (a JPEG, two post ids), the calendar marking it taken, unschedule deleting both.

## His two Instagram accounts: a post on one, on each, or one co-signed (2026-11-10)

**His words**: a photo account and a motion-design account that «parfois publient ensemble, parfois de manière individuelle». **Decision**: three ways, all per post in the Post band — tick ONE account in To (alone); tick both (a post on EACH, two Postiz entries); or tick one and invite the other under «With · Instagram collaborators» (ONE post co-signed: Instagram's `collaborators` setting, the invite accepted in the app). The To ticks in Publishing are only what a new post starts with (said there now). **Rules**: inviting an account unticks it from To and ticking it in To drops the invite (`PostBand`'s `toggle` / `invite`; `publish.compose` refuses both at once); `planPost` offers as `partners` only his live Instagram accounts the post does not go to, and only when it goes to an Instagram account; a story invites nobody; more than 3 collaborators (Instagram's cap) blocks. **Usernames**: an invite needs the Instagram username, and Postiz lists accounts by display name (his: «Steeve Pommier», «📸 Steeve taking photos») — `readChannels` reads `profile` / `username` when Postiz gives it (UNVERIFIED on his instance: the MCP's `integrationList` showed none), and Publishing has «Your Instagram usernames» (`PostizConnection.handles`, `cleanHandle`) which wins; an account with no username is shown but not invitable, its tooltip says where to type it. ## Each account its own variant (2026-11-11)

**His words**: «les réels et les stories, je les fais sur Instagram ; sur Threads et Twitter, je mets des images plutôt carrées ou pas très hautes — publier la même chose sur différents réseaux mais de manière adaptée» (he had just added X, Threads and Bluesky to his Postiz). **Decision** (it reverses lab 1's «one variant per post»): a send is a set of ROUTES, one per ticked account — the variant it takes, Instagram's kind for it, «+ Story» beside it, the long or the short caption. **How a route picks its variant** (`planPost`): the one he picked for that account in this sketch (`PostDraft.variantFor`), else the variant whose FORMAT the account usually takes (`PostizConnection.usual`: `video 9:16`, `picture 4:5` — `variantFormat` = media + `aspectName`; format, not id, because ids are per sketch), else the default variant, else the first it can take. A pick in the band remembers the format at once; a send remembers every route's. So the second sketch routes itself — verified: after one send, another sketch with a Reel and a Still gave Instagram the Reel and X and Threads the still, «usually picture 4:5». **Captions**: two templates — the long one (Instagram, TikTok, YouTube; `DEFAULT_CAPTION`) and the SHORT one (Threads, X, Bluesky — `SHORT_PROVIDERS`; `DEFAULT_SHORT_CAPTION` = title, engine and loop, link, tags), each counted against the shortest limit of the accounts taking it; new words in either take the approval back. **The band**: one row per account (checkbox, name, network; under it the variant menu listing every variant with `— not here` on those its network refuses, the Instagram kind, «+ Story», a mono line `Reel · mp4 · usually video 9:16`); the folded summary groups by what is sent and names NETWORKS (`Reel + Story 9:16 → Instagram · Picture 4:5 → X, Threads`), an account name only when two of one network go. **Stories** go in a SECOND `POST /posts` (same uploads, `post_type: story`, no collaborators) — two entries for one integration in a single request was not risked. Verified headless on a stub with his five accounts (2 Instagram, X, Threads, Bluesky): two uploads (the 9:16 mp4, the 4:5 JPEG), one post with Instagram's entry carrying the mp4 and the long caption and X's and Threads' the JPEG and the short caption, a second post for the story.
