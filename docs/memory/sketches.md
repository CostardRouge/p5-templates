# Sketches

Read before adding, renaming, editing or deleting a sketch, and before touching the generated catalogue or the sketch routes.

## Where sketches live, and the name that no longer exists

2026-08-20 — Sketches are under `src/sketches/<engine>/` — `p5`, `gsap`, `threejs`, `html` — with p5 sketches at `src/sketches/p5/sketches/<category>/<sketch>/`. Nesting creates categories. Commit 4946ea6 ("Standardize on sketch") moved everything out of `src/templates/` and renamed the routes; `docs/`, older commit messages and even a previous version of `CLAUDE.md` still say `src/templates/` or `src/p5-sketches`, and neither path exists. **How to apply**: trust `tsconfig.json`'s `paths` and `jest.config.js`'s `moduleNameMapper`, which agree — `@/p5/*` → `src/sketches/p5/*`, likewise `@/gsap/*`, `@/threejs/*`, `@/html/*`. If a doc points you at `src/templates/`, the doc is stale.

## Old URLs are kept alive by 308 redirects

2026-08-20 — The same rename moved the gallery and editor from `/templates` to `/sketches`. `next.config.ts` keeps permanent (308) redirects for `/templates` and `/templates/:path*`, because shared links, bookmarks, indexed URLs *and stored recording jobs* still carry the old path — Playwright follows the redirect during backend capture. **How to apply**: do not remove those redirects as dead weight; removing them breaks historical jobs, not just old bookmarks.

## A sketch directory has a fixed shape

2026-08-20 — Each sketch dir holds an entry file (`index.js`, or `.ts`/`.jsx`/`.tsx` — the drift test accepts all four) and an `options.ts` exporting `formValues` (the defaults, a plain nested object) and `formConfiguration` (per-field UI config: `component`, `label`, ranges). Those two exports are what generates the parameter form — there is no separate form code to write. Two marker files control visibility: `.hidden-home` hides a sketch from the home showcase, `.hidden-template` from the `/sketches` gallery (`scripts/watch-sketches.mjs`). **How to apply**: copy the shape from a neighbouring sketch in the same category. Nested groups in `formValues` map to `component: "nested-object"` entries in `formConfiguration`.

## The current p5 sketch API is callback registration

2026-08-20 — p5 sketches import the shared runtime and register lifecycle callbacks; they do not define a bare `function sketch( p, options, assets )`. That older signature survives in `docs/SKETCH_CREATION_GUIDE.md` and is the single most common way to write a sketch that does not run.

```js
import options from "@/p5/utils/options.js";
import sketch, { getP5 } from "@/p5/utils/sketch.js";

sketch.setup( () => { /* one-time setup */ } );
sketch.draw( ( time, center ) => {
  const p = getP5();          // the live p5 instance
  const o = options.sketch;   // this sketch's params, from options.ts
} );
```

**How to apply**: `time` is the duration-scaled loop clock (see `docs/memory/architecture.md` on deterministic capture), never raw seconds. Reach for the existing helpers in `@/p5/utils/` — animation, easing, colors, grid, shapes, mappers, audio, webcam, interaction, slides, title — instead of reinventing them; it is a large toolkit and most sketches are mostly composition.

## Versions are added, not edited

2026-08-20 — Variants live side by side rather than replacing each other: `churros-v1-circle` through `churros-v11-perspective`, `rings-v9-flick-reveal` then `rings-v10-magnetic-flyby`. Old versions stay renderable, which matters because stored presets and jobs reference them by name. **How to apply**: a substantial change to an existing sketch's behaviour is a new `-vN` directory, not an edit in place. Edit in place only for fixes — a broken asset path, a bug — where the previous behaviour was not something anyone would want back.

## A sketch name is a public URL now — steevepommier.com frames 44 of them

2026-09-16 — The corollary, learned while carving the `flip` category out of `rings`: **the window to rename or re-home a sketch is before its PR merges**. While a sketch has never been on `main` there is no public URL to break, and moving it costs a `git mv` of its directory, one of its asset folder under `public/assets/images/templates/p5/`, and a catalogue regeneration. Afterwards the rule above applies and the name is frozen. **How to apply**: settle a new sketch's category and name in the same session that creates it — that is the only cheap moment.

2026-08-24 — The personal site's `/motion` section publishes one page per shader sketch, and each page frames this app's `/embed/<engine>/<category>/<sketch>` in an iframe, with `/sketches/<engine>/<category>/<sketch>` offered beside it. The URLs are stored as literal strings in that repo's `src/content/motion/*.mdoc` — nothing is read from this app at build, deliberately, so its gallery keeps rendering when this app is down. **How to apply**: renaming or moving a sketch directory now breaks a live page on another domain, not just a bookmark — the "versions are added, not edited" rule above is what keeps that from happening, and it matters more than it used to. Two settings the site depends on: `EMBED_FRAME_ANCESTORS` unset (its default `*` is what allows framing at all — narrowing it must include `https://steevepommier.com`), and the `#a=`/`#s=` fragment contract in `src/lib/embedOptions.ts`, which the site writes by hand (`#a=desktop`) rather than through the share dialog.

2026-09-02 — That same site now draws **its own control panel** next to the frame, in its own type, and drives the sketch by writing a new `#o=` into the iframe — which the embed's existing `hashchange` listener already applies live. Two consequences here: `/api/sketches/form` is served with `Access-Control-Allow-Origin: *` (GET + OPTIONS, error responses included) because that panel fetches the sketch's `formValues` / `formConfiguration` from the browser at runtime — deliberately not at its build, so its gallery keeps building when this app is down; and the `#o=` fragment is now a **write path used by another origin**, not only a share format. **How to apply**: the hashchange handler in `EmbedSketchClient` and the `o=` codec in `src/lib/embedOptions.ts` are load-bearing for a live page on another domain — same standing as the `/embed` URLs themselves. The route's payload stays free of user data and credentials (it describes a public sketch that must already exist in the catalogue), which is what makes the wildcard origin safe; keep it that way if the route ever grows.

## The catalogue is generated, hook-synced and drift-tested

2026-08-20 — `scripts/watch-sketches.mjs` scans `src/sketches/` and writes three files: `src/sketches/metadata.json` (the catalogue the gallery and editor read), `src/generated/sketchModuleRegistry.ts` (literal `import()` thunks, so each sketch code-splits) and `src/generated/sketchOptionsRegistry.ts`. Three mechanisms keep them honest: `.husky/pre-commit` regenerates and stages them whenever a file under `src/sketches/` or `public/assets/images/templates/` is in the commit; `src/sketches/__tests__/sketches.test.ts` fails if the committed metadata differs from what the generator would produce today, or if a sketch is missing its entry file, options, thumbnail or preview; and `.gitattributes` resolves their merge conflicts automatically (see `docs/memory/tooling.md`). **How to apply**: never hand-edit the three files. Regenerate with `npm run sketch:meta:write`, or run `npm run watch` during development. Registry thunks must stay literal `import()` calls — a computed specifier would defeat the code splitting the generator exists to produce.

## Cut-paper shapes go through the raw Canvas2D path, and need flat corners

2026-08-24 — The postage-stamp silhouette in `photo/photo-stamp-collage` is built with `p.drawingContext` (`beginPath` / `lineTo` / `arc`), not with p5 shapes, because the same path has to be filled once — so the drop shadow follows the notched outline rather than a rectangle — and then reused as `ctx.clip()` for the photo; a `beginShape()` gives neither. Two traps came out of it. **Corner inset**: distributing the notches over the full edge makes the first notch of two adjacent edges overlap, which eats the corner away and leaves a one-pixel diagonal spike — visible only at 8× zoom, and easy to mistake for an arc-direction bug. Reserve a flat corner (`~1.6 × tooth radius`) at both ends of every edge and distribute the notches over what is left. **Arc direction**: walking the rectangle clockwise on screen, every notch arc is drawn with `anticlockwise = true` (decreasing angle) so its bulge points into the paper; flipping that flag turns bites into bumps. **How to apply**: when a sketch needs cut-paper, torn or die-cut edges, copy that traversal; and verify it by cropping the capture around a corner at high zoom, because the artefact is invisible at full canvas scale.

## Lifting a piece out of a photo: carry the crop as a fraction, not as pixels

2026-08-24 — `photo/photo-stamp-collage` can punch the stamp's shape out of the big photo, so the piece reads as lifted rather than copied (`stamp.cutout`, on by default — it is what the reference collage does). Two rules make it hold up. **One resolved crop, two consumers**: the stamp's source rect is computed once and passed to both the stamp and the hole; recomputing it per consumer is how the two silently drift apart. **Fractions, not pixels**: the crop is carried across as a fraction of its image, so a stamp and a photo of different resolutions still line up, and the hole is then given the stamp's own aspect — which makes it the exact region when both show the same image, and a stamp-shaped window on the same part of the frame when they do not. The hole is repainted with the background *and* the grain layer, clipped to the photo: filling it with the flat background colour alone leaves a suspiciously clean patch in a grainy page. **How to apply**: verify this kind of geometry numerically, not by eye — capture with the effect on and off, take the bounding box of the changed pixels, and compare that crop against what the stamp is holding; a mean channel difference of a few units is resampling, anything more is a mapping bug.

## Decorative noise is painted once, never re-randomised per frame

2026-08-24 — Paper grain, dust and speckles are drawn into a cached `createGraphics` layer from a fixed `p.randomSeed`, keyed on canvas size plus the amount, and blitted each frame (`photo/photo-stamp-collage`). Randomising per frame would both cost a few thousand path fills per draw and break the deterministic-capture rule in `architecture.md` — a recorded video would boil. **How to apply**: use `graphics.createAutoResizableGraphics` and null the cache key from its resize callback, so a canvas resize repaints the layer instead of stretching it.

## A sketch's state object is declared through `sketch.state()`

2026-09-02 — `const sketchState = sketch.state( () => ( { … } ) )`, never a plain `const sketchState = { … }`. A module evaluates once, but the same sketch can run as several "sketch" content-item layers next to its own page, and a plain literal is then shared by all of them — parameters bleed between layers and per-size caches thrash. The proxy `sketch.state()` returns behaves exactly like the object (`sketchState.shapes.push`, `state.grid = …`, spreads, `Object.keys`), so nothing else in the sketch changes; pass an **initialiser function**, not an object, when the state holds a `Map`, a class instance or a buffer, so each instance builds its own. The drift test `src/sketches/__tests__/sketchInstanceState.test.ts` refuses the plain literal under the four names in use; a module-level `let` is the same hazard and should move into the state object. Runtime side and the measured cost of getting it wrong: `architecture.md`, "module-level state is per instance now".

## Navigation is client-side; module-level p5 state is what breaks

2026-08-23 — Every internal link is `next/link`. A `HardLink` component (a plain `<a rel="noopener noreferrer">`) used to force a full reload from the gallery and the recordings pages, because p5 sketches did not tear down cleanly and a returning visit could end up with two live sketches. That teardown was fixed, so `HardLink` was deleted — and with it the blank internal referrers its `noreferrer` caused (see `docs/analytics.md`). **How to apply**: if a sketch page ever leaves a canvas behind again, fix the teardown; never reintroduce a hard-reload link, which hides the bug and costs the referrer. The trap it was hiding is real and worth knowing: `src/sketches/p5/utils/sketch.js` keeps the instance in module-level `_p5` and sets it to `null` on destroy, so anything asynchronous that outlives the sketch dereferences null. `_refreshAssets` in `utils/options.js` did exactly that through its own 80 ms debounce — leaving a sketch page threw `Cannot read properties of null (reading 'loadImage')`, reproducibly, but only on the *second* gallery round trip. A full reload had always destroyed the module state along with the document, which is why it never showed up before. The guard is an early return when `getP5()` is falsy, placed **before** the cache is touched: a half-filled `imagesMap` would memoise `img: null` entries that the `if ( !obj )` check never retries. Assume any other module-level p5 helper has the same exposure.

## A per-photo setting is a field of the photo's own list entry

2026-08-26 — When a photo sketch needs a value per photo — a zoom point, a stamp position, a swap zone — the shape is `photo/photo-zoom-point`'s: replace the flat `images` (`images-stack`) with `items`, an `item-list` of `{ photo, …values }`, and have the canvas click write onto the entry that is on screen. `photo/photo-stamp-collage` (stamp position + focus) and `photo/photo-swap-collage` (swap zone) were converted to it. A parallel per-beat array indexed alongside `images` was tried first and rejected by the maintainer: the value must belong to the photo, so that reordering the list carries it along and the form shows it under the photo it belongs to. **How to apply**: the draw loop publishes the indices it drew into the click-handler state (`sketchState.lastFrame` / `activeIndex`), or a click lands on whatever entry the defaults imply rather than the one on screen; the click handler rewrites the whole `items` array (`mergeChangedInPlace` replaces arrays wholesale, it does not merge them element by element) with the other entries passed through untouched; images resolve through `common.getAsset( item.photo )`, not `imageUtils.getImages()`, and `_refreshAssets` still finds them because `collectImagePathsDeep` walks the entire options tree. Where photos are consumed in pairs, one entry still owns the beat: in the stamp sketch the pair's first photo carries the position and the second carries the focus (the focus is a point *inside* the stamped image); in the swap sketch the pair's first photo carries the zone. The cost, accepted knowingly: the `images-stack` bulk drop zone is gone (photos are added a row at a time), and a preset or `/embed` URL saved against the old `images` field renders the default photos — the two sketches are recent and lightly used, and versioning them (`-vN`) was judged worse than one clean shape.

## `item-list` needs a shaped default for every itemConfig it hosts

2026-08-26 — `getDefaultValueForConfig` in `ItemListRenderer.tsx` falls through to `""` for any component it does not name, so an item-list whose `itemConfig` is a `vector2d` used to insert an empty string on "Add Item" and hand the pad nothing to bind to. `vector2d` now defaults to the centre of its own range. **How to apply**: before using an `item-list` with an itemConfig type nobody has used there yet, check that switch — the failure is a silently malformed row, not an error.

## `conditional-group` rebuilds its whole object on a branch switch

2026-09-16 — Switching a `conditional-group`'s type does not merge: `ConditionalGroup.handleTypeChange` replaces the entire group value with `{ [conditionalOn]: type, ...defaults }`, and those defaults come from `getDefaultValueForFieldConfig`, which returns **`config.min` for a slider** and `options[0].value` for a select. So a branch whose fields carry no explicit `default` materialises at the bottom of every range — a depth slider lands on 0, a count on its minimum — and the sketch looks broken the instant someone switches modes. The optional `schema` (a zod object, injected client-side in `injectSketchSchemas.ts` because schemas do not survive the server→client boundary) overrides that, but it exists only for the `36days-of-type-2023-*` sketches. **How to apply**: give **every** field inside a conditional branch an explicit `default:`, and keep every branch's values in `formValues` so a preset saved on one branch still reads. `easing` is not in that switch at all and defaults to `""`, so it needs one too. `flip-v2-grid-cascade`'s `layout` group is the worked example. The switch also **drops the other branch's keys entirely**, and a studio save then writes them back into `options.ts` as a literal `undefined` — harmless while the sketch reads them through `??`, a trap for whoever removes one. Restore real values when you see it.

## The `flip` category: the edge-on frame is the only place anything may jump

2026-09-16 — The `flip` category (`src/sketches/p5/sketches/flip/`, shared beat in its `_shared.js`) is built on one rule. A beat is a half turn from edge-on (-90°) through face-on (0°) to edge-on (+90°), and the next beat **restarts at -90°** rather than carrying on to 180°: both ends are the same plane, so the restart is invisible, and every face stays readable instead of mirrored (past 90° a glyph is seen from behind, and a tube has no front face to hide that). From there, **the edge-on instant is the one frame where anything at all may change discontinuously** — which glyph is on stage, how many cells there are, their offsets, the camera's fit distance — because nothing is on screen to pop. That is why entries of different lengths cost nothing in v1, and why a tile may come back as two in v2. **How to apply**: anything that swaps content on a rotation aligns the swap AND every other discontinuity on the flat frame, and never turns a glyph past its own mirror. "Flat" is a fact about the camera, so a plane's rest orientation is the camera basis by default (`flip.frame` in v1); pinning it to the world axes makes the flat instant drift as soon as the camera orbits. Measured rather than asserted: a y-axis flip collapses the lit bounding box's **width** to ~10 px while the height holds, an x-axis flip collapses the height, and `alternate` does one then the other.

2026-09-16 — Category naming: `letter-flip` was rejected for `flip`, because the genre is not only letters — a shape, a photo or a whole sketch can be the thing that turns — and because the sketch names already carry the detail (`flip-v1-letter-cycle`, `flip-v2-grid-cascade`). The category was carved out of `rings` while its PR was still open, which is the only window where that is free: the moment a sketch is on `main`, its directory name is a published `/embed` URL (see above) and the rename is no longer available.

## A board of turning planes is cards on quads — and a card can itself be shader-baked

2026-09-16 — `flip-v2-grid-cascade` does not raymarch its board **as uniform arrays**, and that narrower claim is the true one. v1 holds 8 glyph planes at 48 capsules each; a board of 64 independent planes unrolls to tens of thousands of capsule evaluations per scene sample, and GLSL ES 1.00 additionally forbids selecting a letter's uniform slice by a uniform-derived index, so every cell would have to loop the entire bank (the restriction v1's `SEG_STRIDE` comment documents). So each face is baked **once** into a card, and the board is that card on turning quads in an offscreen WEBGL buffer composited onto the p2d canvas. Cells are then free, however many there are. **How to apply**: the pattern and its traps come from `text/text-dice` — recreate the buffer when `graphics._pInst !== p` (a re-mount/HMR otherwise draws with a torn-down instance and crashes p5) and clear every cached graphic in `sketch.setup`. Two consequences of baking: the card's hue must **not** depend on time, or every frame is a re-bake, so animated colour rides the per-cell `tint()`; and `image()`'s 9-argument source-rect form does work in WEBGL, which is what makes the fragmentation mode (each cell sampling its own rectangle of one card) possible — inset the SOURCE rect by the same gutter as the destination, or the pieces never quite reassemble.

2026-09-16 — What a card holds is a free choice, and `card.renderer` makes it one: `strokes` rasterises the capsule chain in 2D, `shader` runs v1's own material through `createNoiseFieldRenderer().render({ offscreen: { width, height } })` — an additive mode on the shared GPU renderer that sizes the buffer explicitly, sets `uResolution` to the size asked for rather than the canvas's, and returns the buffer instead of compositing it. That is how a sketch bakes a square texture out of a shader written for a full-screen quad. Two rules come with it: the buffer is the renderer's own and is reused by the next call, so blit it into a graphic you own **immediately**; and bake orthographically, because the card becomes a texture on a quad that supplies its own perspective and a perspective bake applies it twice. **The limitation to state rather than let someone discover**: the lighting is baked face-on, so it does not turn with the tile — near face-on it is v1 exactly, at a steep angle it reads as a lit decal. Per-angle lighting needs the whole board raymarched in one pass, which is a different sketch: capsules in a **data texture** (`texture2D` has no constant-index restriction, so a cell picks its letter freely) and cells found by **domain repetition** instead of looped — a tile turning about its own centre never leaves its own column, so a sample point's cell follows from its (x, y). The trap waiting there is the classic one for repeated domains with different content: the SDF is discontinuous at the cell walls, so the sphere-trace step must be clamped by the distance to the wall or rays tunnel through.

## A whole board DOES fit in one SDF — the obstacle was the lookup, not the marching

2026-09-16 — `flip-v3-tube-cascade` raymarches the entire board in one pass, which the entry above says a uniform-array SDF cannot. Three things together dissolve it, and none of them is a data texture. **The structure is walked, not stored**: the quadtree leaf holding a point is found by at most `depth` iterations of "is this node subdivided at its own beat?", the same recursion the CPU runs in v2 — so nothing is uploaded and the board stays a pure function of the clock. **Everything per-cell is computed, not looked up**: rank, beat, angle, axis, which face — all from the cell's centre. **Only the capsules need indexing**, and the standard `for (F) if (F == face)` loop handles that, executing one inner loop per sample. The price is the sketch's defining constraint: a cell shows ONE GLYPH, so the bank is characters rather than words, which is what keeps the unrolled budget at 8 × 48 — exactly v1's. **How to apply**: reach for a data texture only after checking whether the thing being looked up can be recomputed instead; here recomputing was both cheaper and what kept determinism.

## In a sphere trace, every BOUND must stay above the hit threshold

2026-09-16 — A raymarched board needs two conservative bounds — a box around the whole thing, and a clamp to each cell's walls, because a repeated domain holding DIFFERENT content per cell lets a ray step straight through into a neighbour. Both bounds are returned from `mapScene` as ordinary distances, and that is the trap: a ray that lands exactly on the bounding box gets a distance of ~1e-7 from it, the tracer reads anything under `SURF_EPS` as a surface, and **the bounding volume renders as a solid slab filling the frame**. The wall clamp does the same thing at every cell boundary. **How to apply**: never return a raw bound — `max(boxDistance, slack)` and `min(d, wallDistance + slack)` with a slack comfortably above `SURF_EPS` (0.0025 against 0.0012 here). The bound is a promise about where geometry is *not*; it must never be mistakable for geometry.

## Debugging a flooded raymarcher: separate the field from the march

2026-09-16 — When a raymarched sketch fills the frame with solid colour, reasoning about the SDF is the slow path — it took a long time and got nowhere on the bound trap above. Two throwaway `main()` bodies found it in two renders. First, **render the field**: sample `mapScene` on the plane the content sits in and map the sign to colour (red inside, green outside). That proved the geometry, the cell lookup and the wall clamp were all correct, which eliminated most of the code. Second, **render the march**: run the sphere trace by hand and output `vec4(didHit, steps / maxSteps, t / uMaxDist, 1.0)`. Reading those pixels back numerically said hit on step 1 at t = 4.16 — exactly the camera-to-bounding-box distance, which named the bug outright. **How to apply**: a parameter probe comes first and is cheapest (here, `pullBack 3` showing 11.6% filled — precisely the board's screen area — proved the board was a solid rectangle rather than a near-plane artefact); then the field; then the march. Read the debug pixels as numbers, not by eye.

## A shader-side loop clock closes to ±1/255, not to the byte

2026-09-16 — v2 computes its board on the CPU and its loop wrap is byte-identical (`head = 0` and `head = 1` render the same PNG). v3 computes the same board in the shader and does not: 78 pixels in 176 400 differ, every one of them by exactly 1/255 on a single channel. The cause is float32 — at the wrap the clock reads `12.0 - 0.3` where frame 0 reads `0.0 - 0.3`, and those do not share a fractional part in 32-bit. It is drift on antialiased edges, not a seam, and it is irrelevant to a recorded loop, which renders frames 0…N-1 and never shows both. **How to apply**: keep the byte-equality assertion for a CPU-driven sketch, and for a GPU-driven one assert a bounded difference instead — a structural jump shows up as thousands of pixels differing by tens of levels, which is nothing like this signature.

2026-09-16 — Geometry is shared, materials are not: `flip/_letterField.js` holds the letter→capsule builder and its memo for the whole category, and the shaders stay in the sketches. That split is what lets two renderers of the same sketch draw provably identical geometry, and it is what the `card.renderer` switch means when it says it only changes the material. **How to apply**: verify an extraction like this by re-running the original sketch's measurement, not by reading the diff — v1's lit bounding box still plateaus at exactly 268×262 and 262×305 after the move, which is the whole proof that nothing shifted.

## A cascade must be a pure function of the clock, not an evolving tree

2026-09-16 — The obvious way to write a subdivision cascade is to keep the tree in state and mutate it when a tile goes flat. That version cannot be captured: headless capture renders arbitrary frames and would inherit a different tree, and frame 0 would not match frame N. `flip-v2-grid-cascade` therefore rebuilds the whole tree **every frame** from the loop clock, each node deriving its own beat from its own rectangle — and it still only changes on flat frames, because the value it derives (`generationAt( its own beat index )`) changes exactly when that index does. Loop closure then needs one more thing: the board's generation returns to 0 every `schedulePeriod` beats and the face cycle every `faceCount`, so beats per loop is snapped to their **least common multiple** rather than left to the user. **How to apply**: verify this class of claim by pixel equality, not by reading the code — put the sketch in its manual-head mode and compare `head = 0` against `head = 1` byte for byte (they must be identical), then the same head twice (identical) against two different heads (different). A side effect worth knowing: children take their rank from their own rectangle, so a spatially smooth wavefront order makes a split invisible while `random`/`noise`/high `jitter` make children appear at an arbitrary angle the instant the parent vanishes — that is the anime cut-in, and it is the chaos knob, not a separate mode.

## The `sculpt` category: a seeded lattice the wave lays tubes on

2026-09-21 — `src/sketches/p5/sketches/sculpt/` splits the way `flip` does: geometry in `_lattice.js` (points seeded into a unit volume with a spacing floor, k-nearest links, memoised on the parameters), the animation in `_wave.js` (a rank per position by mode, a pose / hold / withdraw envelope), and the material in the sketch — `sculpt-v1-scatter-lattice` is rings v6/v10's capsule field (`uSegA`/`uSegB` vec4 arrays, `smin`, bounding sphere) with one extra `uNode` array for the bulbs. The maintainer asked for the split up front because further sculpts are meant to draw the same lattice in other styles. Rules that hold across the category, each learned or decided while building v1:

- **Links are computed on REST positions, never animated ones.** Drift, breathing and the cursor's pull move the nodes a link is drawn between, not which nodes are linked; recomputing k-nearest on moving points swaps neighbours mid-loop and a link blinks.
- **The wave lives in the sculpture's own frame.** Ranks come from the unspun, undrifted rest positions, so `motion.spin` turns the wave with the object like a texture. That is what keeps a link's orientation stable — a link is walked from its lower-ranked end to its higher-ranked end so material flows away from the source — and the one mode where an orientation can still flip mid-pose is `cursor`, whose source moves. Accepted rather than hidden behind hysteresis, which would be state.
- **No p5 noise anywhere in the category.** p5 seeds its permutation table from `Math.random` unless `noiseSeed` is called, so a sketch that drifted on `p.noise` would differ between the studio and a capture. `_lattice.js` carries its own seeded value noise (`valueNoise3`) and `driftAt` samples it on a circle in noise space at the point's rest position: whole cycles close the loop, and neighbours drift together instead of tearing their links.
- **Budget: 48 points, 96 links** — v10's proven 96 capsules, plus the bulbs only when `material.nodes > 0`. `nearestPipe` loops the links alone; a bulb takes the hue of the nearest link, which is one of its own, continuous with the tube meeting it and one loop cheaper. Past this budget the answer is a data texture and a spatial grid, deliberately left for a later variant; the sliders are bounded to what v1 renders.
- **The cursor is the only state**, rings v10's chase verbatim (wells in screen space on the CPU mirror of the shader camera, view-parallel offsets, exponential lag on a wrap-aware loop-clock `dt`). With no pointer the wells are empty and nothing converges, so a headless export closes; `cursor.virtual` (circle / lissajous / sweep, stateless on the loop clock) is what puts the effect into an export and what gives the `cursor` wave mode a source without a mouse. Well range and strength are fractions of the canvas's short side so an export at another size deforms the same.
- **The light rides on the camera by default** (`light.follow`, the one deviation from the family's world-fixed `uLightDir`). An orbit turn passes behind a fixed light, and for half the loop the tubes are backlit rims on dark bodies; the CPU adds the rig's yaw to the light azimuth so the sculpture is lit from the same side of the frame all the way round. Off, it is the family's light again.
- **The auto-fit reads the frustum off the shader, not off the fov slider.** `BRAID_CAMERA_MAIN_GLSL` spans uv in [-0.5, 0.5] against `uFocal`, so the frame's true half-angle is `atan( 0.5 / focal )` — roughly half the slider's value (flip v3 fits a half-height-1 plane at `2 × focal` for the same reason). Fitting on the slider's angle cut the sculpture at both edges of a square capture; fitting on `0.5 / focal` leaves the measured margin (lit bbox 33 → 318 px in 360).
- **Every option a headless verification needs is a form field**: `wave.headMode = manual` + `wave.head` (flip v3's scrub), a fixed camera (`orbit 0`, `sway 0`, `yaw 0`, `elevation 0` maps world x/y onto screen right/up), `material.nodes 0` to measure links alone, `interaction.mouse.enabled false` because headless Chromium parks its mouse at (0, 0) and the shared module reports it as a real pointer — a well in the corner that also outranks the virtual cursor as the `cursor` wave's source. Drive it through `/embed#o=`, which re-parameterises live, and read the canvas instead of screenshotting (SwiftShader hangs `page.screenshot`). Two metric traps paid for: in the steady state ~70% of the ranks are active at once (the previous wave's body dominates), so a direction is measured on a thin band (one wave, `rise 0.1 hold 0.05`, spread 1, heads 0.35 vs 0.8) and never on the default envelope; and attraction CONTRACTS the tubes around the well, which shrinks the lit area on that side, so the pull is measured as lit pixels inside a disc around the cursor (attract fills it, repel empties it), never as a centroid shift. A stale `next-server` from an earlier run keeps serving an old build's chunk manifest as 500s after a rebuild — kill it by `pgrep -f "next-serve[r]"` (the bracket keeps the shell that runs it from matching itself) before restarting.

Measured on v1 at 360×360, resolution 0.5: head 0 and head 1 are byte-identical when the hue scroll is off (CPU-driven geometry, `uT` only feeds the hue), every directional mode's thin band moves the lit centroid by 100–130 px in its direction, the virtual-cursor wave's near band sits at x ≈ 245 with the cursor on the right and x ≈ 118 with it on the left, and the pull drops the right-half material's mean distance to the well from 77 to 71 px under attract and raises it to 134 px under repel (attraction is capped at the cursor and never overshoots, so its signal is the smaller one — a threshold above ~5% is a false failure).

**How to apply**: a new sculpt imports `getLattice` and the `_wave.js` helpers and writes only its renderer; if it needs a new wave mode, add it to `rankAt` with its source at rank 0 and its far end at rank 1 (the unit test in `sculpt/__tests__` checks exactly that for every directional mode). Category naming: `sculpt` was chosen knowing `rings-v6-letter-sculpt` already uses the word for sculpting by hand — here it is the sculpture as an object, and the sketch names carry the detail (`-v1-scatter-lattice`).

## `sculpt-v3-vision-relief`: a sheet the camera lifts, raymarched by domain repetition

2026-09-21 — The relief variant does not use `_lattice.js`: its nodes are a GRID (`_sheet.js`, square or hex), because that is what removes the 96-link ceiling. The shader finds a sample's cell with a `floor`, evaluates the beads and the forward links of the 3 × 3 cells around it — each node owns E and S, plus SE and NE when diagonals are on; on a hex lattice only the odd rows own diagonals, which covers all six neighbours exactly once — and reads everything per node from one RGBA texture: the height on 16 bits (8 bits visibly steps a slow rise), the x / z jitter in the other two channels. `createNoiseFieldRenderer` grew a `textures` param for it (NEAREST + CLAMP data textures on units 1 and up, re-uploaded every render), the same additive shape as `offscreen`. Two rules make the neighbourhood exhaustive, and both are enforced in code: the sphere-trace step is clamped to the cell wall plus a slack above `SURF_EPS` (flip-v3's lesson, or a ray crosses into a cell whose links it never evaluated), and the jitter is bounded by `jitterBudget` to half a cell minus the hex parity shift, the widest tube and a margin — a node jittered to its wall with a fat tube would otherwise reach into a cell two away, unseen. Drift counts against the same budget.

- **A silhouette is a surface, traced from landmarks** (`_silhouette.js`): capsules per phalanx and per limb, rounded polygons for the palm (indices 0·1·5·9·13·17), the face oval (the 36 `FACE_OVAL` indices) and the torso, discs for the head and the wrists; each node reads a signed distance and `shapePresence` feathers it (plateau / dome / rim). Sizes follow the entity's own scale (wrist → middle knuckle, shoulder width), so a near hand gets fat fingers. Landmarks are read raw off `getTaskResult` — the shared collectors only expose fingertips and 8 pose points — with the layer's mirror rule copied (`visionFlip`, as hand-cutout does). The DeepLab mask is the other route (`detect.mode = mask`): `_desiredVisionTasks` honours `vision.segmenter.enabled`, which the sketch injects into the options it hands the interaction layer instead of adding a block to the shared form, and `processMask` dilates + blurs once per result.
- **Tubes only join lifted neighbours, which is the whole answer to the O.** `links.require = both` gates a tube on its LOWER end, adjacency is the grid's (never a nearest-neighbour recomputed on the lifted set, which would bridge a hole), and there is no `reach` slider: a link two cells long needs a 5 × 5 neighbourhood, five times the SDF cost, so the proposal's "portée" was dropped. A tube fattens in over `links.fade` above the threshold, so it appears by growing rather than popping.
- **Dynamics run on the loop clock's dt, in seconds to 95%** (`rateFor`): rise / hold / fall per node, a rank inside the silhouette (`liftRank`: radial, sweep, noise) that delays the lift by its share of `lift.stagger`, contagion by `spreadTargets` (fading to 1 / (radius + 1) at the radius, not to 0 — at radius 1 the first version did nothing). Framerate-independent by construction; the unit test integrates at 30 and 60 fps to the same value.
- **Idle is fully on from frame 0 when nothing has ever been seen**, and its paths start and end OFF the sheet (a cosine with an amplitude beyond the half-width), so a headless export — no camera, `interaction.mouse.enabled false` — opens on a resting sheet and is a pure function of the frame index; the only loop residue is the fall's tail as the hand leaves. A live session that sees a hand fades the virtual one out over `idle.fade` and brings it back `idle.after` loop-seconds later (wrap-aware).
- **A sentinel must never enter `smin`.** The first build flooded the frame with a flat mosaic, one colour per cell: a dark link returned `1e9` and `smin( bead, 1e9, k )` computed `mix( 1e9, 1.19, 1.0 )`, which float32 cancels to ~0 — a "surface" everywhere on the bounding box's top face. Found in one probe round (beads only 0.7% hit, links only 0%, both 89.9%), not by reading the SDF; the `join()` helper skips `EMPTY` on either side before calling `smin`. The probe rig is worth keeping: a bare WebGL page compiling the sketch's exact fragment (extracted from `index.js`, chunks imported from `braidShader.js`, which has no imports) with a swapped `main()` that writes hit / steps / t / last-d — no Next rebuild per iteration.
- **The camera is top-down by construction** (tilt / yaw / zoom / projection as sliders, so bindable; `light.follow` rides the yaw as in v1). Ortho at tilt 0 maps one cell to `frame.cellPx`, exactly the CPU mapping the landmarks use, so a landmark lifts the node under the pixel it was seen at; the mouse is unprojected through the rig onto the y = 0 plane so its brush lands under the pointer at any tilt. The keys (`camera.tilt/yaw/zoom/fov/orbit/sway/swayCycles/fog`) were chosen so a move onto the shared `cameraRig` does not break presets.

Measured headless (SwiftShader, 240×300 at resolution 0.5, 24 columns, tilt 0, hue scroll off, mouse / touch / vision off, `idle.headMode = manual` — the scrub every headless check of this sketch needs): the resting sheet is 0.8% lit and two captures 5 s apart are byte-identical; the virtual hand parked at head 0.125 puts the lit centroid at x = 151 px, at head 0.375 at x = 85 px (canvas centre 120), and the same head twice differs by 0 px; a 10-cell disc with a 1.5-cell `rim` lights its band to 41.5% while the disc inside r < 3.3 cells stays at 1.4% under `require = both` — under `any` the inner disc rises to 4.9% as the rim's inner nodes link one cell inward. Two things about reading it: tubes at this scale are under a pixel wide, so a hand reads as +0.4% lit, not as a bright blob — measure centroids and regions, never a global lit fraction; and the shipped defaults fly the hand on the loop clock, so a single capture can land on an off-sheet moment (0.8%, identical to rest) — capture twice or park the hand.

## A second grid sculpt, and why it is its own module

2026-09-21 — `sculpt-v2-letter-relief` is a grid sheet like v3 above and shares no code with it, because what it uniquely holds is the LINKS: `_mesh.js` (unit-tested in `__tests__/mesh.test.ts`) gives every cell four of them (E, S, SE, SW), stored and traced exactly once, so the mesh is the subject rather than a by-product of lifted nodes. It therefore carries two textures per frame where v3 carries one — offsets plus a 16-bit height, and the four link weights. Everything that decides (the grid, the rise order, the beat envelope and its handover, the links) is plain JavaScript over typed arrays, and the shader never sees a letter. **The naming is the lesson**: this module and v3's were both written as `_sheet.js`, in parallel sessions, and one of them had to be renamed before it could merge. A shared module in this category is named for what it uniquely holds — `_mesh.js` the links, `_sheet.js` the heights, `_lattice.js` the scatter, `_wave.js` the ranks — never for the shape it happens to draw. Same story one level down: `cellHash01( i, j, seed )` sits beside `_lattice.js`'s `hash01( seed, ...parts )`, whose arguments come in the other order.

2026-09-21 — **Readability, the letter's version.** v3 gates a tube on both its ends being lifted, which is enough when the shape is whatever the camera sees. A letter needs the stricter rule, because the ink itself is the subject: the mask is the RASTERISED ink (a fill test, so the counter of an "o" is never on it, where an outline chain from `letterPaths` would be), and `links.rule = ink` additionally requires a link's MIDPOINT to be on the ink — one sample on a mask already in memory, and the only thing that keeps the eye of an "e" open whatever the neighbourhood. The `endpoints` rule bridges any counter thinner than a cell; the test shows both. Rasterise into a `createGraphics` (`pixelDensity( 1 )`, red channel kept as bytes, `remove()` in a try/catch — it throws on `_pInst._elements` in this p5 build, as `text/text-dice` also found), memoise it, and centre the glyph on its INK's bounding box: `textAlign( CENTER, CENTER )` sits a capital a tenth of the sheet too low in agiro. Density is the third lever and nothing replaces it (≈ 8 cells across the thinnest stroke); `text.weight` thickens the ink instead, at no GPU cost.

2026-09-21 — **Trace everything that TOUCHES the block, not just what it owns.** With links owned per cell, the obvious scan — the 3 × 3 block's own links, with a slack — is sound for marching and still wrong: a link owned by a cell two away is then seen from one side of a wall and not the other, so a tetrahedron normal straddling that wall reads two different fields, and every fat tube shimmers with noise along the cell boundaries. The fix is to trace every capsule touching the block (its nine beads, its nine cells' links, and the outer ring's links whose far end lands inside) exactly once, and to bound the step by one whole cell past the sample's walls — which `MAX_OFFSET`, keeping a point in the middle 90 % of its cell, is what makes safe. Two more things this sketch paid for, both general: geometry thinner than twice `SURF_EPS` must be skipped outright rather than drawn thin, because anything within the threshold is a hit and a height of 0 decodes from 16 bits to a few 1e-6 (the sheet speckled with near-zero spheres); and a texture of packed numbers must reset `UNPACK_PREMULTIPLY_ALPHA_WEBGL` before uploading — p5 turns it on for its own images and it is persistent GL state, so every RGB byte gets multiplied by the alpha byte, silently corrupting any channel that carries data rather than opacity. `render({ textures })` does that now for every caller.

## A grid sculpt's empty air is a distance, not a march

2026-09-22 — Both grid sheets (`sculpt-v2-letter-relief`, `sculpt-v3-vision-relief`) were slow for one reason: every ray over the RESTING sheet crawled down through the slab one cell per step (the wall clamp), paying the full block scan (v2: 25 cells, ~114 texture fetches) at every step, on air. Two facts make the air cheap and stay rigorous. **The box is the frame's real extremes**, not `HEIGHT_MAX`/`HEIGHT_MIN` × height: on a rest frame it collapses onto the sheet and the ray reaches it in a step. **A per-cell ceiling (v2: and floor) travels in one more data texture** — `packBounds` in `_mesh.js`, `packTops` in `_sheet.js`, over the shared `_extremes.js` window max/min (separable, tested against brute force) — holding the highest (lowest) height within a 5 × 5 window, rounded UP (down) to the byte. Why 5 × 5: everything the scan traces has an endpoint in the 3 × 3 block, so both endpoints lie within two cells of the sample. Above `top × height + margin` the vertical gap is a distance to everything the scan could find and the scan is skipped for one texel; the lateral wall clamp STAYS in the air, because a cell three away is outside the window. The margin carries the widest radius, the whole fillet (`smin` bulges k/4 past its primitives) and a slack above `SURF_EPS`, folded into the margin rather than applied after (`max( gap, slack )` alone would overstep at the fusion slider's minimum). v3 derives the radius from the local top itself — radii grow with height, so a resting neighbourhood's ceiling sits at its bead and not at the sketch-wide `uBoundR` — and mirrors it as a floor (heights are ≥ 0). v3 also decides a dark link BEFORE fetching its far node (`require = both`, no rest tube, near end under the threshold ⇒ the gate is under it whatever the far end reads — exact), which on a resting sheet is most of its fetches; and it now skips any radius under `2 × SURF_EPS` outright (v2's `MIN_RADIUS`): a link fading in below that rendered as a hairline that came and went with the step sequence, the "V" the before/after diff caught hanging under the lifted patch. **How to apply**: the ceiling is a promise about where geometry is NOT, so anything that can widen a primitive (a new radius term, a taper, a lift) must widen the margin; and a new bound is verified by the frame diff (`scripts/bench-sketch.mjs --diff`, `testing-and-ci.md`): trace noise is speckles spread over EVERY edge with the lit fraction unchanged; a clustered patch is geometry cut or added. Measured at 540 × 675 under SwiftShader (ratios, not desktop times): v2 2466 → 1412 ms/frame, v3 2819 → 1352 ms/frame at its 0.95 default (1607 → 836 at 0.7). Two things the comparison taught: v2 is a pure function of the frame index, so its diff is read straight; v3 integrates heights on dt and the live frames before the clock is pinned leave a HISTORY (a faster build renders more of them, so "frame 0" showed the hand elsewhere and a fading second patch) — diff it with the hand parked (`idle.headMode manual`) after a settle long enough to reach the plateau, never with the shipped moving hand.

2026-09-22 — **Tried and rejected for the uniform-array lattices (v1, v4)**: folding a primitive into the union only when it can change it (`if (e < d + k) d = smin(d, e, k)` — exact, since `smin` returns `d` once `e ≥ d + k`; v4 additionally skipped the rounded cone behind the capsule that bounds it). Measured SLOWER under SwiftShader on both (v1 594 → 653, v4 1102 → 1278 ms/frame): a data-dependent branch inside a 96/128-iteration uniform loop costs more than the fillet it saves, and nothing here can measure a desktop GPU. Not shipped. What would move v1/v4 is fewer primitives per step — the spatial grid in a data texture the category entry above already names — not a cheaper primitive. The fringe look (below) is the one thing that makes them cheaper today, by skipping AO and the specular.

## The fringe look: the artefact kept, the body dropped

2026-09-22 — Every sculpt thumbnail carries the same artefact at every tube's silhouette: a dithered rainbow fringe with thin-film bands just inside it. It is `shade()`'s own rim — `iridescent( phase + uShimmer * fres )` slides the hue through several cycles as `fres → 1` at grazing angles, `base * fres * uRimStrength` brightens it, the trace converges slowly there (rays that exhaust `MAX_STEPS` drop out as background speckle) and the 0.7 blit dithers it. The maintainer asked for a mode that draws the design the way that artefact looks instead of the lit tube, and chose this reading over the other candidate (the hairline links hanging under v2's letter, drawn as 2D strokes). So `material.look = fringe` keeps exactly that term and nothing else: `base` (the same fresnel hue slide) times `uFringeBody + uFringeGlow * pow( 1 − n·v, uFringeWidth )` (shipped: width 1, glow 3, body 0.1 — width 3 and glow 1.4 were tried first and read as a dark blob with a hairline rim; the band must be wide and the glow high once the lit body is gone) — no diffuse, specular, occlusion or shadow, which also makes it the cheaper look on the uniform-array lattices. **How it is wired**: `braidShadingGlsl( { look: true } )` is an opt-in on the shared chunk — off, the GLSL is what every other tube sketch always had, guarded by `utils/__tests__/braidShader.test.ts` (no `uLook` leaks, the four uniforms declared exactly once) — and the sketch sets `uLook` / `uFringeWidth` / `uFringeGlow` / `uFringeBody`. The form is a `select` plus three always-visible sliders, deliberately not a `conditional-group`: a branch switch rebuilds the whole `material` object and would reset thickness and fusion to their minima (see the conditional-group entry above). `look` defaults to `tube`, so every preset and `/embed#o=` link without the key renders as before. **How to apply**: a tube sketch outside the category takes the same opt-in and the same four fields rather than a second look mechanism; a new look is one more `uLook` value and one more early return in `shade()`, never a second shading chunk.

## `sculpt-v4-sphere`: the lattice with a skin, on the shared rig

2026-09-21 — The fourth variant is the one the index's open item waited for: it wanted the lattice and the wave, so it took them instead of shipping its own. It was first built in a parallel session as a self-contained module (its own sampler, linker, birth fields and three "lives") plus its own camera rig, and both duplicated what `main` had merged meanwhile; the rebase rebuilt it on `_lattice.js`, `_wave.js` and `utils/cameraRig.js`, keeping only what was genuinely new. **What it adds to `_lattice.js`**: `skin`, a share of the points placed exactly on the unit sphere on a Fibonacci spiral — even by construction, disordered by `1 − spacing`, seed-independent at spacing 1 — before the volume is filled, the inner points kept at 0.9 of the radius so the two populations read as two; and `max` / `budget`, so a sketch that sizes its uniform arrays larger than v1's 48 / 96 asks for them (v4 runs 72 points and 128 links, ~330 uniform vectors). A skin of 0 is byte-identical to the old builder. **What stays in the sketch**: the tapered tip — the drawn segment is iq's exact rounded cone with `|r1 − r2|` clamped below the segment length (past that the square root goes NaN and the tracer reads "no hit": flickering holes on freshly born tubes), and the head fraction rides in the hue vec4 as `identity + 2 · round( 100 · head )`, peeled off with `floor( w / 2 )`, so it costs no uniform; and the rig in place of v1's orbit camera, with the fog and the ray cutoff read off the real eye–target distance because the rig's `position` offsets the eye. **Two GLSL ES 1.00 refusals** paid for, invisible to `next build` (a shader is a string) and reported only as `Shader compile error` in the browser console: `packed` is a reserved word (so are `input`, `output`, `half`, `fixed`, `static`, `inline`…), and a uniform array may be indexed by a loop counter but never by a function parameter — the loop reads `uSegA[s]` and passes the vec4s down. Probe a new shader on `next dev` with a Playwright console listener before spending a production build on it. **Dropped from the first build, on purpose**: three custom "lives" (`pass` / `build` / `pingpong` — `_wave.js`'s rise / hold / spread envelope covers the first two and a reverse-order withdraw is not expressible in a modular phase), camera-space wave fields (the category rule is the sculpture's own frame), links taken in rounds and an inward "veins" mode; ask for them back only with a sketch that needs them. **Measured** (SwiftShader, 220×260 at resolution 0.5, one wave, rise 0.12 / hold 0.05, drift, hue scroll and pointers off): head 0 and head 1 are byte-identical; a still sculpture has its centre disc 64% lit with skin + inside, 76% inside only, 30% skin only; `camera.lookAt.x` 0 → 0.9 slides the centroid 39 px on a 220 px canvas while an eye offset keeps it (the rig aims at the target) and only shrinks the coverage; and taper 0 versus 0.5 differs at rest by exactly 1/255 on ~1% of the pixels — the rounded cone and the capsule rounding differently on antialiased edges, not a shape change — so compare those two with a bounded difference, never byte equality.

## The tangible camera is a shared rig, not a per-sketch orbit

2026-09-21 — `utils/cameraRig.js` (tested in `utils/__tests__/cameraRig.test.ts`) — tilt, spin, roll, fov, distance, eye offset and target as sliders (each one bindable, so an LFO on the distance breathes and a knob on the tilt is a hand on the crane), `fit` from the subject's bounding sphere and the canvas aspect so every export aspect frames the subject, and whole-cycle motion (spin turns, tilt sway, dolly, bob) that closes with the loop. Conventions are braid's: spin 0 puts the eye on the −z side, +x is screen right, y is up; tilt is clamped to 89.9°, a top view to the pixel with a basis that is always defined. `CAMERA_RIG_UNIFORMS_GLSL` + `CAMERA_RIG_MAIN_GLSL` replace a sketch's own camera `main`; `screenRay` / `hitPlaneY` are its exact inverse, which is how a pointer lands under the point it covers on screen. The four pose controls declare `knob.1–4` (tilt, spin, distance, roll); a sketch that needs its knobs elsewhere overrides those entries. **How to apply**: a new raymarched sketch takes this rig rather than a bespoke orbit, and the auto-fit arithmetic above — the frustum's true half-angle is `atan( 0.5 / focal )`, not half the fov slider — is exactly what `fitDistance` does; do not re-derive it.

## `snapKeys` / `excludeKeys`: one matching rule, in `slides/keyMatch.js`

2026-08-30 — The breakdown's key lists and the montage's `lerpParams` snap check now share `matchesKeyList` (`src/sketches/p5/utils/slides/keyMatch.js`, re-exported from `breakdown/deriveSteps.js` for existing importers). An entry matches a leaf by **full dotted path, bare leaf name, or ancestor path** — the ancestor rule is new and is what makes "colors" a legal entry covering `colors.*`. Before it, a group name pruned the step walk in `deriveSteps` (which tests each node on the way down) but was silently ignored by `startValues` and by `lerpParams` (both of which only ever see leaf paths), so a group typed into `excludeKeys` dropped the step yet still animated the values. A bare mid-path segment is deliberately *not* an ancestor match ("cell" does not cover `grid.cell.size`): a group is addressed by its path. **How to apply**: any new consumer of a user-supplied key list imports this helper rather than re-implementing the two-line comparison — that is how the three copies drifted.

## The `lcd` category: a 1-bit framebuffer first, pixels last

2026-09-23 — `src/sketches/p5/sketches/lcd/` draws monochrome LCD screens; `lcd-v1-flipper-zero` is a pocket multi-tool's 128 × 64 orange-backlit panel cycling six screens (menu, frequency analyzer, raw capture, card read, typed message, dithered plasma) with a Bayer dissolve. The maintainer asked for "a flipper sketch" and, asked to choose between a pinball machine and a new `flip` variant, answered "Flipper Zero" — **"flipper" is ambiguous here** (French for pinball, and a `flip` category exists), so ask. Category named for the genre (`lcd`), detail in the sketch name, same rule as `flip`. Three shared modules, each named for what it holds: `_framebuffer.js` (a `Uint8Array` + clipped primitives, `XOR` ink, Bayer threshold, `hash01`), `_font.js` (a hand-drawn proportional 5 × 7 font with descenders — browser text thresholded at 7 px is mush; digits stay full width so a changing readout does not shift; accents are stripped via NFD, `é` → `e`) and `_panel.js` (the Canvas2D panel: backlight falloff, unlit cells, each dark cell's shadow on the backlight, glare). **Why the raw context**: up to 8192 cells per layer are one `rect()` path filled once — ~36 ms per 1080 × 1350 frame under SwiftShader; per-cell p5 calls would be thousands of calls. **Rules that keep it capturable**: a scene is `( frame, s, { seconds, … } )` and pure; jitter is `hash01` of an integer tick; every repetition runs `repeats( seconds, perSecond )` whole times per segment. Unlike most sketches the rates are per REAL second (`resolveAnimation(…).duration`), not on the nominal 12 s clock, so a longer loop shows more UI rather than slow motion. The LCD's slow-crystal smear is the frame 0.06 s earlier rendered again underneath — no history, so still a pure function of the phase. No device artwork (mascot, logo, shell) is reproduced; icons and wording are generic. **How to apply**: a sibling screen (another handheld, a Game Boy, a Nokia) reuses the three modules and writes only scenes; verify a scene's raster with a Node script that paints it straight to a PNG before touching the app (the modules import nothing from p5). Measured: the same frame twice and frame 720 vs frame 0 are byte-identical; no preview video was recorded.
